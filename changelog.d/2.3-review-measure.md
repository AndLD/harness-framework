Added: `harness review measure` prints the measurements of a harness review that a script can decide, which the reviews ran by hand with `wc`, `grep` and a loop over the Markdown files: the words of the always-loaded set (the entry file, what it imports and the root files that import it) with the rows and words of its `procedures` block apart (M6), the normative and exception words of that set (M20), the rows of the rule map by status, the hand-written rows apart from the generated ones (M5), the Markdown files that no link reaches (M7), the highest fan-out and fan-in of a document (M21), and the references that break the dependency rule between layers, listed (M3). It counts as the earlier reviews did, so a number compares with the previous report, and it prints each number against the ceiling of the project's harness review bindings (a table row `Number | Baseline | Ceiling`, or `Aspect | Number | Budget`): it exits with 1 when a number is over its ceiling. The harness review method cites the command in the step that measures; the bindings stub has the new rows (all with `—` until the first review proposes the ceilings), and a project that took the version reads the rows it wants into its own bindings. Nothing is required of a project.
