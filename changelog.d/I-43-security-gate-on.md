Security: the `update-branches.yml` workflow of the GitHub preset now grants read at the top and `contents`, `pull-requests` and `actions` write on its job only (the probe S3-001 flagged the old top-level write grants, as it did for the release template before I-37). The framework's own profile turns `checks.security` on and accepts the broad local rule `Bash(node *)` in `security.allowedRules`, which the flow's own permissions name (the owner's decision of 2026-11-08). Required of a project: run `harness sync` and take the new `update-branches.yml`, or move the write grants of your own workflows from the top to the job; turn `checks.security` on once `harness check security` passes.
