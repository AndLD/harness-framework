Security: every action of the workflows the GitHub preset and the stacks generate is pinned to a full commit with its version in a comment (`actions/checkout@<40 hex> # v4.4.0`), and the framework's own workflows are too; a moved tag no longer runs someone else's code in CI or in the release workflow, which holds a write token. The core rule `sec.pinned-actions` returns (it waits for the owner's approval), and `checks.security` stays off in this repository until I-43. Required of a project: run `harness sync` and take the new workflow files, or pin your own `uses:` lines (`harness check security` lists the ones still on a tag, S2-004); turn `checks.security` on once it passes. Keeping the pins current: enable Dependabot version updates for the `github-actions` ecosystem in the host's settings or in `.github/dependabot.yml`; it raises one pull request per action that moves the commit and rewrites the version comment, and the required checks run on it.
