Added: `harness check markers` (part of `harness check all`, so of `docs:check` where a project runs it) fails on a line that starts with 7 or more `<` or `>` characters and a space or the end of the line, in a tracked Markdown or JSON file: the marker of a merge conflict that was committed unresolved. `harness branch update` no longer commits a file it resolved to the branch's side when that file holds such a line; it names the file and leaves the merge in progress. A project has nothing to do; a file that holds such a line on purpose (a document about conflicts) writes it inside a line or an indented block.
