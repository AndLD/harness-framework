Added: adapters of a project's own repository. A folder `harness-adapters/<axis>/<name>/` that the profile file selects as `local:<name>` (in `adapters.stacks`, `adapters.runtimes` or `adapters.host`) is loaded by the tools like a preset, so a project whose stack, agent runtime or host the framework has no preset for (Go, GitLab, Copilot) no longer waits for a release. A sync, `harness migrate` and `harness check vendored` leave the folder alone, and `harness rollback` restores it with the rest of a migration. `harness check adapters` holds the manifests to their contracts, and the new check `local-adapters` (part of `harness check all`) runs the conformance suite on every local adapter; `harness migrate` runs it with the new version's suite and stops before it commits when an adapter no longer meets the contract, naming the adapter, the failed checks and the migration notes that say what changed. The guide and the procedure `new-adapter` offer both ways and say how a local adapter is sent upstream. A local adapter imports nothing from the framework's tools by a relative path. A project with no `harness-adapters/` is unaffected; a project that wants one takes the version with the sync.
