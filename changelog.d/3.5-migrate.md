Fixed: after `harness sync` to a new version `check generated` could fail until `sync --local` ran again, because the sync generated the managed files with the tools of the old version. `sync` now only places the files and updates the lock, then starts the new command `harness migrate` of the new version in a new process, which regenerates them. A project whose `sync` is older than this version runs `node harness/tools/harness.mjs migrate` itself after the sync.
