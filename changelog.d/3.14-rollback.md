Added: `harness rollback` and the safeguards that make a migration undoable. `sync` refuses to start on the production or the integration branch and with uncommitted changes, and records the commit and version it starts from in the lock; `migrate` commits the migration as one commit (the sync's changes included); `rollback` puts every file that commit changed back to its content at the start and removes the files it added, and nothing else. After the `sync` of an older version, `migrate` takes that sync's files into its commit and refuses any other uncommitted change.
