Fixed: the migration of `0.3.0` no longer writes prose into the release table's id column. Of an old table's cell, only the ids the tools read (a task of a phase, "Phase N" of a phase that exists, an issue) stay in "Tasks, in order"; the words around them go to "Notes", and the migration says so. A release the project skipped on purpose (a row with no task whose words say "skip") gets the new status ⏭ (skipped on purpose, in the releases template and the legend of the file); it is never "next" in the plan index. An order of phases written as arrows beside the table, which the tools do not read, is kept in "Notes" and the migration now prints a required action that says how to keep it (name the phases as "Phase N" in the table). The migration of the earlier versions is unchanged.
