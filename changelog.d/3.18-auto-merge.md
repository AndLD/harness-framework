Added: auto-merge for the pull requests an agent may merge without asking. The profile switch `host.autoMerge` is on where `host.protection` is `true` and off where it is `false`; on, the core rule has the agent enable the host's auto-merge (squash) as the last step of a task, the shell guard refuses `gh pr merge --auto` into the production branch, on a release or hotfix branch, on a pull request not into the integration branch and where the switch is off, and the rule `agent.no-auto-merge` (ask first) applies where it is off. `harness host protect` allows auto-merge on the repository, the GitHub adapter scaffolds `update-branches.yml` (it brings the integration branch into the pull requests waiting on auto-merge) and the trigger `workflow_dispatch` of the CI template, `harness branch update [--previous <branch>]` merges the integration branch into a stacked task after the squash merge and resolves the conflicts only that squash causes, and the bootstrap asks the host what it offers and sets `host.protection` and the host (`--no-host-setup` skips it). The runtime adapter says how a session waits for a pull request, and the final message lists the pull requests that wait for the owner. See the migration note of the version for what an existing project does.
