Added: the cold-start probes of a project name the areas they exercise, so that taking a version reruns the right ones. Each probe in the harness-review bindings has an `Areas` column (the areas of the migration notes) and the words read at the last review; the bindings stub of a new project has four starting probes. `harness probes <from> <to>` prints the probes to run again for the versions taken and, for an area no probe covers, the framework's starting probe (`core/reviews/harness/starting-probes.md`); `harness check probes` holds the area names.
