Added: a project can have procedures of its own. The new profile role `paths.procedures` names a folder of procedure files in the format of `core/procedures/`; the skill generators package them for the selected agent runtimes (the note of origin in a skill names the project's file), the `procedures` block of the entry file lists them after the framework's, and `harness check generated` fails on a stale skill of one. A name that the framework's procedures have too is an error. The CORE scan does not read the folder; the project classifies it in its layer map. Nothing to do for a project that does not set the role.
