Added: the release order in a file of its own. A project that ships versions can name a file in the new profile role `paths.releases` (by default `docs/development-plan/releases.md`): one table `Release | Status | Tasks, in order | Consumers | Notes` (status ⬜ planned · 🟡 developing · 🏷 a development version cut · ✅ released) and a list "Not scheduled", from the new template `core/plan/releases-template.md`. The tools read the order of the tasks from it instead of the section "Order of development" of the plan index (the session start and `harness plan summary` included), the plan index shows the current and the next release in a generated block that links to the file, and `harness check plan` refuses in it a backlog item (`B-<n>`) and an id that exists nowhere, and an index that keeps the section beside the file. A project without the role loses nothing: its tools read the section of the index as before, and a project that ships no versions needs no file. The migration of `0.3.0` moves a table of the section into the file, sets the role and leaves the block in the index; an order written in prose (arrows of phase numbers) cannot be read by the tools and is left as it is, with a message: write it as the table of the template, set `paths.releases` and run `harness plan summary`.
