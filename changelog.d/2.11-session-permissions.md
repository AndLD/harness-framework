Changed: a session that a flow starts gets the flow's `permissions` setting by the means of the runtime's application (a minor addition to the agent-runtime contract, version 2: an adapter whose application takes none still conforms). The Claude Code preset starts a desktop-app session in the setting's mode (`permission_mode` of `start_session`, which the app takes at or below the orchestrator's own mode and refuses above it); the app's start takes no tools, so `harness flow dispatch` names the tools of `allow` as allow rules for the project's settings (`.claude/settings.json`, or the local `.claude/settings.local.json`), which the owner adds. Before this change a session ran in the orchestrator's mode whatever the setting said. The "step started" line of a flow's log gains `· **Permissions:** <mode>` after the model when the flow sets a mode; a line without it still reads as before. A project whose flows set `permissions` and start sessions should add the tools of its `allow` list to its project settings, or its unattended sessions are refused each tool that the mode does not allow.
