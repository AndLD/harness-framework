Changed: a phase of the plan is a folder, `phases/phase-<n>-<slug>/`: `README.md` is its index (goal, order, exit criteria, and a task table that `harness plan summary` generates from the task files), `<id>.md` is a task, `<id>.log.md` is its log beside it, and `log.md` is the phase-wide log. A resuming agent reads the index and one task file instead of the whole phase, and a finished task writes only its own log. `harness check plan` holds the layout, the session-start hook prints the newest next step across the logs and the open tasks, and `harness plan split <phase>` (and the migration script of this version, for the open phases) splits a one-file phase and rewrites every link into it. The tools still read the one-file layout. The phase template became a phase-index template and a task template.
