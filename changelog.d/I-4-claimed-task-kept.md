Fixed: the migration script of `0.2.0` no longer moves a task that a branch claims to the issue queue. A task in hand (claimed by a draft pull request) that was still ⬜ was read as not started, so it became an issue under a new id and the phase was closed without it. The script now keeps a ⬜ task for which a branch of the repository, local or remote-tracking, is named `<type>/<task id>-<slug>`, and says which it kept. The procedure `update-framework` says to set the task in hand to 🟡 before the `sync`, because the task is then never read as not started. Nothing else to do.
