Changed: every version has a migration note, a development version included: `migrations/<x.y.z>-dev.<n>.md` says what a project does when it takes that development version from the previous one (the previous development version of the same `x.y.z`, else the previous final version) and is frozen once the version ships; the final note stays the complete story. `harness migrate` and `harness probes` read the notes of the versions after the project's own up to the target, leaving out the development notes of an `x.y.z` when its final note is among them. `harness release --dev` now refuses a version without its note, as the final release does, and writes a stub (the changelog fragments added since the previous release, the areas, and a `TODO` in the required actions) when the note is missing; a `TODO` left in the required actions stops any release. The release guide and the procedure `release` put the note before every cut. A project with its own release flow adds the note of the development version before it tags it; nothing else to do.
