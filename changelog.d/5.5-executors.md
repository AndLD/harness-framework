Changed: the agent-runtime contract is at version 2 and gains the logic role `executors` (`executorsFor(profile)`), how an orchestrator of a flow hands a step to a worker: a `session` it starts and controls (with the hooks and CI wake-ups of a session), a `subagent` for a short step of analysis, or `manual` (the owner pastes the prompt and the report). Each executor returns the means to start a worker with a model and an effort, continue it with a next prompt, fetch its full final report and read its context. The Claude Code preset maps the desktop app's sessions, the command line (`claude -p`, continued with `--resume`) and subagents; the Cursor preset is a stub with the manual executor only. New: `harness flow dispatch <n> <step> [--context <percent>]` picks a step's executor, decides with `reuse: auto` whether the previous step's worker continues it (the same repository, model and effort, related steps, its context below the new setting `reuseLimits.context`, 40% by default, no stop and no pause longer than the prompt cache lives, fewer than `reuseLimits.steps`, 3, steps run) and prints the means; the flow-log template gains a `Worker:` field, which the next dispatch reads. A runtime adapter of the project's own repository (`harness-adapters/runtime/<name>/`) must now fill `executors`: copy `executors.mjs` from the skeleton and return `{ manual }` when the runtime offers no automation; a project that uses the presets has nothing to do.
