Changed: the stack contract grew where the Python preset needed it, all additive for a stack that exists: `harness coverage summarize` writes the neutral summary from the raw report of one local run (for a tool that does not write it itself); `coverage-merge` gets `{ root, pkg }` as a second argument; an `ignore-files` entry may carry a `pattern` and an `example` for a tool that excludes paths with a setting; the release tool reads and writes the `version` of the `[project]` table of a TOML file; and `.nvmrc` is a file of lines in the node-ts preset, so that a project with two stacks bootstraps. A stack adapter of your own needs no change. The new-adapter guide has a section on what a stack learns the hard way.
