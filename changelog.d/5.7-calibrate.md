Added: `harness flow calibrate [--min <n>] [--subscription <id>]` proposes new coefficients for the runtime adapter's usage table from what flows measured in `usage.jsonl`. It pairs each step's start and end samples, drops the windows that a reset cut, takes the median use per SP of each subscription, model family and step kind (tokens per SP converted to percent per subscription where the runtime reports them, since whole percents are coarse on the larger subscriptions), prints each proposal beside the table's figure with the number of steps behind it (at least 3), compares cold and warm starts and says whether `reuse: auto` pays off (otherwise set `reuse` to `never`), and sets whole flows against their steps. It never writes: the procedure `run-flow` says to run it at the end of a flow and to accept a proposal by a pull request that changes the table. Nothing to do for a project that uses the presets.
