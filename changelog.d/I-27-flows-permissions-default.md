Added: the profile role `flows.permissions` (`{ "mode", "allow" }`, in the runtime's own words) is the default of a flow whose settings have no `permissions` of its own, which wins; `harness flow dispatch` takes it and `harness check flows` checks it. Optional: a project that wants its flows' workers to start in a mode other than the runtime's strictest sets it once in the profile file, instead of in each flow.
