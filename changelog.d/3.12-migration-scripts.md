Added: migration scripts. A version may ship `migrations/<version>.mjs`; `harness migrate` runs, with the new version's tools, the scripts of every version after the project's own up to the target that the lock does not record, in version order, records them (`migrations` in `harness.lock.json`), and prints the migration notes of those versions in order. A lock without the record counts as `0.1.0` with nothing applied. The migration test bootstraps a project from each released tag and migrates it to the current tree. A script checks its starting state and can run twice.
