Changed: the framework's commands and hooks are quiet by default. `harness check all` prints the problems and one line (`N checks passed`), `harness check <name>` one line on a pass; the steps of the pre-push gate and the project checks (`checks.project`) write their output to a file and print nothing on a pass, and on a failure the path of the file and the failing lines, at most `output.maxLines` of the profile file (default 40). `--verbose` restores the full output of `check` and `gate`; a script that read the output of a passing check must use it. New: `harness flow dispatch <n> <step> --brief` prints the step, its worker and how to start it, and the line to log, without the guidance for reading its report and the usage.
