Added: `probes.run` in the profile file (`auto`, `ask`, the default, or `disabled`; the ignored `harness-profile.local.json` overrides it on one machine) for how taking a version handles the cold-start probes of the project, which are a session each and read thousands of words. The end of the output of `harness migrate` and of `harness probes` says what the mode asks of whoever takes the version: run them (`auto`), ask the owner first and run them only on a yes (`ask`), or leave them (`disabled`). The procedure `update-framework` follows the mode. No command starts a probe itself yet, so `auto` and `ask` are instructions; a project that takes the version and wants no probes sets `disabled`.
