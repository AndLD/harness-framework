Fixed: a push from a linked Git worktree no longer lets the gate's tests rewrite the repository's Git config. Git runs the pre-push hook of a linked worktree with `GIT_DIR` set to `.git/worktrees/<name>`, and the steps of `harness gate` inherited it, so a test that ran `git init` or `git config` in a temporary folder set `core.bare = true` or a new `core.hooksPath` on the pushing repository. The hook now unsets the variables that point Git at a repository (`git rev-parse --local-env-vars`) before the project's setup script, and the gate starts every step without them. A project takes the fix with the sync; a repository a push already damaged needs `git config core.bare false` and its `core.hooksPath` set back by hand.
