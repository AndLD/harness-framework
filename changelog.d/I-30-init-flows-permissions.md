Added: `harness init` asks for the profile role `flows.permissions` (the default permission mode of the workers of the flows, and the tools they may use without asking) when a selected runtime adapter lists the modes it offers in the new optional manifest key `permissionModes` (Claude Code lists its six; Cursor lists none and is not asked). An empty reply sets no role, a mode the runtime does not list is refused, and `--set flows.permissions.mode=<mode>` answers it without a question. Required of a project: nothing.
