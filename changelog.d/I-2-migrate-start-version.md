Fixed: `harness migrate` took a project that an older `sync` (before `0.2.0`) had updated for `0.1.0`, because that `sync` replaces the version in the lock and keeps no record of where the project was: the start recorded for `harness rollback` named `0.1.0`, and the notes of the versions the project had already taken were printed again. `migrate` now reads the version from the lock of the last commit (the commit the migration starts from) when the lock has no record; a lock that no commit holds still counts as `0.1.0`. Nothing to do for a project.
