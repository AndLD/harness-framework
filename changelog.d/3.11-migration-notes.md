Added: a migration note for every version, `migrations/<version>.md` (from `0.1.1`), in a fixed shape: what changed for a project, the areas touched, the required actions with their checks, the optional actions, how to verify. `migrations/` is distributed with the framework. With `release.migrations` in the profile file, `harness release` refuses a version without its note, writes the areas the version touched into it (derived from the files that changed in `core/`, `tools/`, `adapters/` and `profile/` since the previous tag, by `migrations/areas.json`) and links the note from the changelog entry. The README says how a project takes a version, also across several.
