Added: a backlog for the feature requests, beside the issue queue and optional like it. The profile role `paths.backlog` names a folder with an index of the open items (generated by `harness plan summary` and shown in the plan index), a file per item (`B-<n>.md`, from the new backlog template, with `Source:` set to `report` and the link of each report, `owner` or `agent`), and `archived/`. Nothing in it is built until the owner puts an item into a release or asks for it by name; "Work the issue queue" and "Fix I-<n>" do not approve one. `harness reports plan` has the relation `feature`, `reports candidates` compares the backlog too, the session start prints a line about it, and an issue that moves to the backlog keeps its number (`B-1, formerly I-6`), which the issue queue never gives again. A project without the role has no backlog; a project that sets `paths.backlog` gets the folder, its indexes and the block of the plan index from the next `harness plan summary`.
