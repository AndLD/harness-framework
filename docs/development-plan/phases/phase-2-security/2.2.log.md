- **Decisions of the task:** (1) the settings check's broad rules follow probe S4-002: a bare tool, an edit rule that is not a named folder of the project (or lies in the settings, the hooks or Git), a shell rule with an interpreter, package runner or fetcher and any argument, or a destructive command with a wildcard; a prefix such as `git *`, a named script (`node tools/harness.mjs *`) and an exact command are not broad, because the shell guard limits them; `security.allowedRules` lets a project accept a rule. This repository's `Edit(docs/development-plan/**)` is a test case that passes, `Edit(**)` one that fails. The owner may tighten it. (2) A caret or tilde range in a manifest counts as bounded (the lock file pins it); a range with no upper bound, `latest`, `*` and an address without a commit are open. (3) `check security` is not in `check all` until `checks.security` is true, because this repository does not pass it yet.
