# 3.12 — Migration scripts, run in order, and a test that every old version migrates

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP · **Needs:** 3.5 · **Log:** [3.12.log.md](./3.12.log.md)

**Migration scripts, run in order, and a test that every old version migrates**: the mechanical changes of a version (a moved file, a renamed profile key, a split phase) are code, not instructions to an agent. (1) A version may ship `migrations/<version>.mjs`, whose step checks its starting state and can run twice without harm. (2) `harness migrate` (3.5) runs, with the target's tools, every script not yet applied, in version order, and records the applied ones in the lock, so a jump from `0.1.0` to `0.3.0` runs the scripts of every version between; a lock without the record counts as `0.1.0` with nothing applied. It then prints the notes (3.11) from the old version to the new one, in order, for the agent or person to follow. (3) **The migration test**: CI bootstraps a project from each released tag and migrates it to the current tree; `check all` passes. Needs 3.5 first. Verified by the migration test from `0.1.0` and `0.1.1`, and by a fixture where a script runs twice without change. The owner's decision of 2026-11-03.
