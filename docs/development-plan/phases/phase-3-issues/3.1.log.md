### 2026-11-03 — the host adapter gives the address, the bootstrap writes it
- **Branch:** `feature/3.1-repository-url` — done. It started from `feature/3.18-auto-merge` (both change the bootstrap and the host adapter).
- **What was built:** a new optional role of the host contract, `repository-address` (logic-optional): `repositoryUrl({ slug }) → string`. The GitHub adapter fills it (`repository.mjs`: `https://github.com/<slug>`). The bootstrap (`withRepositoryUrl` in `tools/lib/host-setup.mjs`, called in `bootstrap()` before the files are written) sets `repository.url` when the profile file has none and the adapter has the role; an address in the profile file is the owner's. A host adapter without the role leaves it empty, as before. The manifest schema lists the role as logic-optional, the contract table names it.
- **Decisions / deviations from the plan:** the role is optional, so an existing adapter still passes the conformance suite (design §1.4: a minor change). The role is a function and not a manifest default, because the address is made from the slug, which a static default cannot be.
- **Verified by:** `tools/lib/host-setup.test.mjs`: a project bootstrapped with `init` has `repository.url` `https://github.com/acme/shop`, and its first release (on `release/0.1.1`, with one changelog fragment) writes `[Unreleased]: …/compare/v0.1.1...HEAD` and `[0.1.1]: …/releases/tag/v0.1.1` with no `undefined`; an address in the profile file is kept; no adapter, or one without the role, invents none. `npm run docs:check` (the manifests are held to the contract), `npm test`, lint, typecheck.
- **Problems / blockers / findings:** none.
