### 2026-11-03 — a defect of `harness branch update`, found by using it
- **Branch:** `bugfix/3.18-branch-update-tip` — done ([#37](https://github.com/AndLD/harness-framework/pull/37)).
- **What happened:** used on the branch of task 3.3 after the squash merge of 3.18, the script resolved `tools/runtime-hooks/session-start.mjs` to this branch's side because develop's content equalled the tip of the previous branch. But the branch of 3.3 had been made from an older commit of the previous branch, and the tip had gained the changes of 3.9 (which the previous branch had merged from develop) since: "this branch's side" lacked them, and the resolution would have dropped them silently. It was seen in `git diff origin/develop` before anything was pushed; the merge was undone.
- **Fix:** the script takes the previous branch's tip into this branch first when it is not an ancestor, so that this branch's side has all of the previous work; a conflict in that merge stops it with the merge in progress. Tests: a fixture in which the previous branch goes on after this one was made from it (the old script fails it), and the conflict case.
- **Next step:** none for this task; the three stacked branches of `0.1.2` (3.3, 3.1, 3.2) are brought in with the fixed script after this merges.
- **Verify with:** `npm test`
