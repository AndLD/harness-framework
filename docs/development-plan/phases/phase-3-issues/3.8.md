# 3.8 — A leak found by a consumer has no path into the framework, and blocks that consumer until a release fixes it

**Status:** ✅ · **Agent:** C2 · **Size:** 2 SP · **Log:** [3.8.log.md](./3.8.log.md)

**A leak found by a consumer has no path into the framework, and blocks that consumer until a release fixes it**: after 3.7 a consumer whose sync finds a word in `core/` cannot take the version, and nothing says how the framework hears of it. (1) A recorded exception in the consuming project's profile file: the file, the word, the link to the upstream report and the framework version it holds for. `check core` accepts the hit while the lock is at that version, and fails on the exception after a sync to another version, so it cannot outlive the fix. (2) The report path: an issue template of the framework's repository for a word found in `core/`, and a rule in the framework's README: a confirmed leak is a defect, a task of the open-ended phase, fixed in a patch release; an ordinary word is answered with `productGeneric` and the vocabulary of 3.7, never by renaming the framework's own words. (3) The release procedure tags a development version first (`x.y.z-dev.n`), so that consumers can sync it and run the scan before the final tag. Verified by a fixture project with an exception that passes `check core` at its version and fails after a sync to the next one, by the issue template and the README rule, and by the release procedure's new step. Depends on 3.7. Found by the closing review of the extraction (H-20261103-01).
