# 3.19 — The framework's tests that `harness sync` copies fail in a pinned project

**Status:** ⬜ · **Agent:** C1 · **Size:** 2 SP

**The framework's tests that `harness sync` copies fail in a pinned project**: `tools/` is distributed with its tests, and 10 of 329 fail in a project that took `v0.1.1` (8 on `v0.1.0`): two tests read `harness/harness-profile.json`, the framework repository's own profile file, which is not distributed ("the framework profile refuses a tool name of each class…", "the vocabulary of the framework core is sorted…", ENOENT), and the adapter, init, bootstrap and skills tests assume every preset is present, while a project vendors only the adapters it selects. Nothing breaks for the project today because its CI does not run them. Either do not distribute the tests that need the framework repository's own files, or make them skip when those files or adapters are absent; a test that runs in a project must pass there. Verified by running `node --test harness/tools/**/*.test.mjs` in a scratch project synced to the development version, with one stack and one runtime. Reported by AndLD/bot-rts (task 17.18): [issue 30](https://github.com/AndLD/harness-framework/issues/30), closed by its pull request.
