# 4.1 — `paths.procedures`: a project's own procedures

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP

**`paths.procedures`: a project's own procedures**: A profile role `paths.procedures` names a folder of procedure files in the format of `core/procedures/`; the skill generators and the `procedures` block of the entry file take the project's procedures with the framework's, and a name that both have is an error; the CORE scan does not read the project's folder; `harness check generated` fails on a stale skill of a project procedure. Verified by tests on a project with one procedure of its own (packaged for the selected runtimes, listed in the block, a colliding name refused). The framework's own repository uses it for its own recurring work (a framework change: a core rule, a check, a profile role). Design §8.1 already says so; this builds it.
