# 4.7 — Templates for an RFC and a risk register

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP

**Templates for an RFC and a risk register**: the framework gives a project a template for a design record (RFC) that a task requires before implementation, and one for a risk register, which the plan method already names as the owners of those contents (`phases.md` section 6, plan method section 4) but for which it ships nothing. The scaffold writes them once into a new project, beside the glossary and the register of open items; the document map gets an optional role for each; a project that has them already adds nothing. Verified by the scaffold and bootstrap tests, the CORE scan (0), and a bootstrapped scratch project that passes `harness check all` with both. The structure checks of the glossary and the register are not extended here: whether a check is wanted is decided with the data of the extension probes. Ships in `0.2.0-dev.2` (the task is independent of the consuming project's run of `dev.1`); if that run finds a blocker, the task moves to `0.3.0`. Added on 2026-11-04 from the discussion of 4.6, because without these templates the procedure that records an RFC or a risk (4.6) has nothing neutral to point the agent at.
