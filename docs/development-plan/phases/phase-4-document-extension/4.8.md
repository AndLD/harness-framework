# 4.8 — A migration note for every version, development versions included

**Status:** ⬜ · **Agent:** C2 · **Size:** 5 SP

**A migration note for every version, development versions included**: a development version has a note of its own, `migrations/<x.y.z>-dev.<n>.md`, in the shape of the other notes, that says what a project must do when it takes that version from the previous one (the previous development version of the same `x.y.z`, or the previous final version for the first). It is frozen once the version ships, so a project that followed it never finds it changed. The final note `migrations/<x.y.z>.md` stays the complete story from the previous final version, and the scripts stay named for the final version (they check their starting state and run again without harm). `harness migrate` prints the notes of the versions between the project's own and the target by one rule: the notes of the versions after its own up to the target, except that the notes of the development versions of an `x.y.z` are left out when the final note of it is among them (the final one covers them). `harness release --dev` refuses a version without its note, as the final release does, and makes a stub listing the changelog fragments and the areas when the note is missing; the areas of a development note are those touched since the previous tag; a placeholder left in the required actions stops the release. The release guide and the procedure `release` put the note before the cut of every version, development or final, and say who writes it. The first use is the note of `0.2.0-dev.1` (what changed for a project, the required actions each with its check, the optional ones). Verified by the tests of the note listing and selection, of the release, of the migration test (a project bootstrapped from a released tag takes a development version, then the next, then the final one, and reads the right notes at each step), and by the scratch run of the procedure `update-framework` from `0.1.0` to the development version. Added on 2026-11-04; it must be done before `0.2.0-dev.1` is cut.
