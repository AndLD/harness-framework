### 2026-11-04 — every version has a note, development versions included; the note of 0.2.0-dev.1 is written
- **Branch:** `feature/4.8-dev-migration-notes` — done.
- **What was built:** (1) *Selection* (`tools/lib/migration-notes.mjs`, `selectNotes`): the notes of the versions after the project's own up to the target, without the development notes of an `x.y.z` when its final note (a note, not only a script) is in the range. `migrate` prints them by it, and `harness probes` (`touchedAreas`) reads the areas by it; the upper bound of the notes is the target itself, while the scripts keep the bound of the final version of a development target. `listMigrations` lists notes named `x.y.z-dev.n.md`; a script named for a development version is not listed (scripts are named for the final version). (2) *Release* (`tools/lib/changelog.mjs`): `release` and `release --dev` both require the note; the previous release of a development note is the previous development tag of the same `x.y.z` (tags without `v`), else the previous final tag (`previousTag`); the areas are the diff since that tag. A missing note writes a stub (`noteStub`: the changelog fragments added since that tag for a development version, all of them for the final one, the areas, and a `TODO` in the "What changed" and the required actions) and stops; a `TODO` left in the required actions stops the release (`placeholderProblems`). A dry run writes no stub. (3) *Documents:* `migrations/README.md` (a section "Development versions": the rule, who writes the note and when, the stub), `docs/operations/releasing.md`, the procedure `release`, `update-framework`, the README rows of `migrate` and `release`, the profile document. (4) *The first use:* `migrations/0.2.0-dev.1.md`, from the fragments of the version and the task files, its areas from `harness release --dev --dry-run` on a scratch release branch.
- **Decisions / deviations from the plan:** the stub is written for the final release too, not only for `--dev` (one rule: a missing note is a stub and a stop). The `TODO` is checked in the required actions only, as the task says; the stub puts it in "What changed" also, as a reminder, and a note that keeps it there is not stopped. The "tag of the previous release is not in this clone" error now applies to a development version also.
- **Verified by:** unit tests of the selection, the previous tag, the stub and the placeholder (`migration-notes.test.mjs`); of the listing and the notes printed by `migrate` for dev.1, dev.2 and the final version and for the jumps (`migrate.test.mjs`); of the release with and without `--dev`, the stub, the placeholder and the second development version (`project-checks.test.mjs`); of the areas of `harness probes` (`probe-areas.test.mjs`); the migration test takes a project bootstrapped from the newest tag through dev.1, dev.2 and the final version and reads the right notes at each step (`tests/migration/released-tags.test.mjs`).
