### 2026-11-04 — undo through Git, with a check
- **Branch:** `feature/3.14-rollback` — done. It needs 3.12, so it branched from that task's branch while its pull request was open, and took `develop` in after the squash merge.
- **What was built:** `tools/lib/migration-guard.mjs` (the preconditions), `migration-git.mjs` (the Git calls), `rollback.mjs`. (1) Since `sync` places the files before `migrate` runs (3.5), the refusal of a dirty tree and of the production and integration branches is made by `sync` before it touches a file; it records `migrations.start = { commit, version }` in the lock. `migrate` run after the `sync` of an older version (which cannot record a start) accepts exactly what a sync writes (`harness/`, the lock, the managed files) and refuses any other uncommitted change; it records the start itself (the commit has not moved) and refuses on a protected branch too. (2) `migrate` commits everything it and the sync changed as one commit, `chore(framework): migrate to <version>`. (3) `harness rollback` finds the commit after the recorded start (its parent must be the start), restores the files it changed from the start and removes the files it added, in the working tree and the index; it refuses with uncommitted changes and leaves the result uncommitted. (4) `tests/migration/released-tags.test.mjs` migrates from every released tag, rolls back and requires an empty diff against the starting commit and no added file left.
- **Decisions / deviations from the plan:** a folder that is no Git repository (a fixture) is not checked and not committed. The migration is detected as pending when the lock's version differs from `migrations.version`, so `migrate` on a project that is already at its version only regenerates (no commit, no refusal). Rollback also restores a file the agent changed after the migration, if the migration changed it too (it restores "every file the migration changed"); the agent's commits stay in the history.
- **Verified by:** `tools/lib/migrate.test.mjs` (a sync refused on a protected branch and with uncommitted changes before it touches a file; one commit that records its start and rollback that restores only the migration's files and leaves the agent's commit; the sync of an older version followed by `migrate`, refusing a foreign change), and the migration test from `v0.1.0`, `v0.1.1`, `v0.1.2`; `npm test`, lint, typecheck, `npm run docs:check`.
