### 2026-11-03 — a pinned project scans its vendored `core/`
- **Branch:** `feature/3.7-pinned-core-scan` — done. The claim was opened first.
- **What was built** (`tools/lib/core-scan.mjs`):
  - `frameworkCoreScan(root)` says which folder a project scans and whether it is the pinned copy. A pinned project with a Git source scans `harness/core` with its `terms` and the terms of `harness/adapters`; a source folder outside the project is still scanned where it lives; the other modes are as before.
  - `core/vocabulary.json` holds the words the core uses on purpose (124 words, singular; the scan also skips the plural). The scan skips such a word for the profile's term lists (stack, product, project values), not for the adapters' words, and a line with a vocabulary word and a real hit still reports the hit. A version with no vocabulary file has an empty one, so the consuming project passes against `0.1.0`.
  - A hit in the vendored copy names the file, the line and the word, and the way out of its term list: `terms.productGeneric` for an ordinary word of the product list, a narrower `terms.stack` or `terms.projectValues`, or an upstream report and staying on the current version.
- **Decisions / deviations from the plan:**
  - The vocabulary is a file in `core/` (distributed with the core) rather than a list in the tools, so that a consumer's scan uses the list of the version it has vendored.
  - The vocabulary applies to the project's own CORE documents as well as to the vendored copy.
  - The 3.8 exception (a recorded hit that holds for one version) will attach to the problems this scan returns; nothing of it is built here.
- **Verified by:** a pinned fixture (`tools/lib/project-checks.test.mjs`) whose vendored core holds a product word: `check core` fails with the message; the same fixture passes with the word in `productGeneric`, and passes with the word in the vocabulary; unit tests of the vocabulary, the messages and the invariants of the list (sorted, used by core, hides none of the framework's own terms). The consuming project of the extraction (`AndLD/bot-rts`, read only): `check core` passes with these tools on its `0.1.0` copy, and its terms pass against the current `core/` with the vocabulary.
- **Problems / blockers / findings:** none.
