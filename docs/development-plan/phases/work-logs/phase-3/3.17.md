### 2026-11-03 — the guard resolves the repository of each Git command
- **Branch:** `feature/3.17-guard-repository` — done. Started from `develop` after the release of 0.1.1.
- **What was built:**
  - `refusal` of `tools/lib/guard.mjs` takes `cwd` and `branchOf`. It follows a `cd` or `pushd` before a command (relative to the directory it runs in; a `cd` inside parentheses ends with them; `popd`, `cd -`, a variable or a pattern make the directory unknown), `-C` (several, in order), `--git-dir` and the variables `GIT_DIR`, and judges the command by the branch of that repository. The branches are kept per repository, so `git -C <clone> checkout -b feature/y` moves only that clone's branch.
  - A repository it cannot resolve (an unknown directory, a path that is no repository, `--work-tree` alone) is judged as on a protected branch, with a message that says it cannot tell and what to do (`cd <path>`, `git -C <path>`, create the branch).
  - `tools/runtime-hooks/guard-shell.mjs` passes `branchOf`, which reads the branch with `git symbolic-ref` in the directory (or with `--git-dir`), `''` for a detached head and null for no repository.
  - Without `branchOf` the old behaviour holds (every command is judged by the one branch), so the other callers and tests are unchanged.
- **Decisions / deviations from the plan:**
  - A push to a protected branch is refused by its destination from any repository, as before; the repository decides only the commit and the push without a destination.
  - The shell parser reports the depth of parentheses, so a `(cd other && …)` does not move the commands after it; without that, `(cd <clone on a task branch> && git status); git commit` would have judged the project's commit by the clone.
- **Verified by:** `tools/lib/guard.test.mjs` (a fake `branchOf`: every form of `cd`, `-C`, `--git-dir`, `GIT_DIR`, both ways, the subshell, the unresolvable cases, a branch made in the other clone) and `tools/runtime-hooks/hooks.test.mjs` (real repositories in a temporary directory, through the hook script, both ways); `npm run docs:check`; `npm test`; `npm run lint`.
- **Problems / blockers / findings:** none. The Git hooks (`pre-commit`, `pre-push`) run inside the repository they act on, so they needed no change.
