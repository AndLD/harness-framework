- **What was built:** both things the task allows. (1) The python scaffold writes, for each package of the stack, `<package>/pyproject.toml` (a workspace member that is not built, with `pythonpath = ["src"]`), `<package>/src/app.py` (a typed function) and `<package>/tests/test_app.py`; a project with no package gets `src/app.py` and `tests/test_app.py` at its root and a `[tool.pytest.ini_options]` in the root `pyproject.toml`. The python manifest says: run `uv lock` once and commit `uv.lock`; CI installs with `uv sync --locked` and is red until the file exists. The new-adapter guide says so for any stack.
- **Decisions / deviations from the plan:** the lock file itself cannot be scaffolded (no tool writes it without resolving against the network), so CI of a new project stays red until the first pull request commits it; the task's wording, "say so … or scaffold a first module that makes both pass", is met by doing both: the module makes `mypy .` and `uv lock` work, and the step says what is left.
