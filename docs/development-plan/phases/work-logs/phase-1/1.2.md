### 2026-11-02 — the Cursor preset, native and compat, unverified in a live session
- **Branch:** `feature/1.2-cursor-preset` — done. The claim was opened first.
- **Decisions / deviations from the plan:**
  - **Mode** is decided by the profile: `claude-code` among `adapters.runtimes` makes the preset compat (`mode.mjs`). Native writes `.cursor/hooks.json` (`hooks.mjs`) and the skills under `.cursor/skills/` (`packaging.mjs`);
    compat writes neither, and `harness check scaffold` fails on a framework hook in `.cursor/hooks.json` there (it would run twice). `harness adopt` adds the framework's entries to a project's own hook file in native mode (`adoption.mjs`).
  - **`.cursorignore` is a managed block, not a scaffolded file**, so that the sync regenerates it without touching the project's lines. That needed three changes in the framework: (1) the markers of a block may be `# harness:begin <id>` lines
    (`managed.mjs`: the file's own markers say which style, and `appendBlock` adds a block at the end of a file); (2) a generator may `expand` into several blocks and mark them `append`, so the sync makes the file or adds the block to the project's file
    (`vendor.mjs`, `runtime-blocks.mjs`); (3) a new optional runtime role, `managed-blocks` (`managedBlocks(profile)`), in the contract and the manifest schema. Because the sync adds the block itself, `harness adopt` needs no extra step for an existing `.cursorignore`.
  - **`skillPath(procedure, profile)`** now takes the profile and may return nothing (compat mode), so the skill generators of `skills.mjs` pass it through.
  - **Entry file.** Cursor reads `AGENTS.md` itself and the preset writes no `.mdc` file, so a Cursor project whose entry file is another name fails `harness check scaffold`.
  - **Samples.** The Cursor event samples moved from `tests/fixtures/events/` into the adapter's `events/` (the six that `conformance.json` names, and the compat one); `pre-tool-write-source.json` is new. They are written from the documentation, and the folder's README says so.
  - **Unverified**, as decided on 2026-11-02: the README of the adapter opens with it and holds the owner's checklist for a live session (native and compat); the manifest description and the changelog fragment say it.
  - The guards do not set `failClosed` (as the Claude Code preset sets nothing alike): a hook that crashes lets the call proceed and the Git hooks and CI hold the rules. The checklist names the open points: `tool_input` fields of `Write`, the answer channel on exit code 2, `$CURSOR_PROJECT_DIR` in a hook command, the form of `paths` in a skill.
- **Problems / blockers / findings:**
  - Switching a project from native to compat (adding `claude-code`) leaves `.cursor/skills/` behind; the generated files are no longer checked there, so the project removes the folder. (The README says compat writes none; not automated.)
  - The `enforces` rows of the Cursor manifest say "native mode"; in compat the Claude Code rows are the true ones, and a project with both lists both.
  - Scratch bootstraps (`--runtime cursor` and `--runtime claude-code,cursor`) pass `harness check all`; the full proof of every combination is task 1.5.
