### 2026-11-02 — the Python preset, by the new-adapter procedure
- **Branch:** `feature/1.3-python-preset` — done. The claim was opened first.
- **The preset** (`adapters/stack/python/`): uv workspaces (`uv sync --locked`, `uv.lock`), pytest with coverage.py (branch coverage), ruff (rules E, F, I, B, UP, ANN, T20; `ruff format`), mypy strict; `gate.mjs`, `coverage.mjs`, `format.mjs`,
  `ci-jobs.mjs`, `scaffold.mjs` with a test each, and real coverage.py reports as the conformance shards. It passes the suite (13 checks), and the commands were run for real in a scratch project with uv, ruff, mypy, pytest and
  coverage.py: lint, typecheck, format check, tests with coverage, `coverage summarize`, and `check-changed` refusing a changed file at 75% against the gate of 90.
- **Deviations from the procedure, fixed in the procedure** (section "What a stack learns the hard way" of `core/contracts/new-adapter.md`, and a step in `core/procedures/new-adapter.md`):
  1. coverage.py writes no neutral summary, and names files relative to where it ran. New command `harness coverage summarize` (the local gate's step after the tests), and `merge(shards, { root, pkg })`.
  2. The ignore setting is `extend-exclude` in a TOML file, not a line: `ignore-files` entries may carry `pattern` and `example` (manifest schema, `harness check scaffold`, the suite).
  3. The release tool read JSON only: it reads and writes the `[project]` version of a TOML file (`readVersion`, `writeVersion`); the preset's `defaults` set `release.lockCommand` to `uv lock`.
  4. `.nvmrc` is needed by every stack (the host workflow sets Node up from it) but node-ts wrote it as text, so a project with two stacks could not bootstrap: both write it as a line.
  5. A lock file cannot be written by hand: the scaffold writes none, the new project runs `uv lock` once, and CI (`uv sync --locked`) fails until it is committed. Different from node-ts, whose empty lock lets CI pass at once.
  6. The suite runs `uv --version` (every command of the defaults), so the framework's CI sets uv up.
- **Decisions:** pytest cannot follow a changed file to its tests, so a touched package runs its whole suite and only the changed files are held to the gate; the metrics are statements, branches, functions and lines (statements equal lines in coverage.py);
  coverage.py is run with `--rcfile` pointing at the root `pyproject.toml`, so a package keeps `src/` and `tests/`.
- **Problems / blockers / findings:**
  - **For 1.5:** a project with both stacks bootstraps now, but each stack emits the jobs `static` and one per coverage package for *all* of `coveragePackages`, so the generated `ci.yml` has duplicate job ids (`static`, `web`, `api` twice).
    The jobs of a stack should be its own: its packages only, and an id that does not clash (the proof of §3.4 covers node-ts and python together, so it fixes this).
  - The first push of a new Python project fails CI until `uv.lock` is committed; the next steps of the bootstrap do not say so yet (the stack file of the project should).
