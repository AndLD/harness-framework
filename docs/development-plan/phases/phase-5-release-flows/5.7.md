# 5.7 — Calibrate the usage estimate from what flows used

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP · **Needs:** 5.6

**Calibrate the usage estimate from what flows used**: `harness flow calibrate` reads `flows/usage.jsonl`, drops the samples that a window reset cut, takes the median per model and step kind (tokens per SP where tokens exist, converted to percent per subscription, since whole percents are coarse on the larger subscriptions), compares cold and warm starts, and proposes new coefficients with the number of samples behind each; it never writes them. The procedure `run-flow` says when to run it (at the end of a flow), how a proposal is accepted (a pull request that changes the coefficients of the runtime adapter, with the comparison), that `reuse` defaults to `never` when warm starts do not pay off, and the limits of the data (the windows are the account's, so the owner's parallel work pollutes a sample). Verified by tests on a fixture of samples (a cut sample dropped, the medians, the cold and warm comparison) and by `npm run docs:check`.
