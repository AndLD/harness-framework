### 2026-11-04 — executors in the runtime contract, the reuse rule and `harness flow dispatch`
- **Branch:** `feature/5.5-executors` — built, branched from `develop` as it is on the remote.
- **What was built:** (1) The runtime contract (version 2) gains the logic role `executors`, `executorsFor(profile) → { session?, subagent?, manual? }`: each executor is
  `{ means, wakeups, cacheMinutes, start, continue, report, context }`, and each operation returns a list of *means* (a tool call, a command, an answer already in hand, or what
  the owner does), never runs a worker itself (`core/contracts/runtime.md`, "Executors"; the schema's `x-roles`; design §4.2 and §12). (2) Claude Code
  (`adapters/runtime/claude-code/executors.mjs`): `session` by the desktop app (`start_session`, `SendMessage`, `list_events` for the full report, `get_usage` for the context) or the
  command line (`claude -p --model --effort --output-format json`, `--resume`); `subagent` by the agent tool (no CI wake-ups, no context reading, so never reused). Cursor: a stub, manual
  only. The skeleton has a red `executors.mjs`. (3) `tools/lib/flow-executors.mjs`: the framework's manual executor (for a runtime that offers none and a project with no runtime), the
  pick of a step's executor, the previous worker read from the log (the new `Worker:` field of the "step started" entry), the reuse rule `decideReuse`, and `dispatchStep`, which
  `harness flow dispatch <n> <step> [--context <percent>] [--at <time>]` prints. (4) The flow setting `reuseLimits` (`context` 40, `steps` 3, an optional `cacheMinutes`), checked by
  `harness flow check`. (5) The procedure `run-flow` (steps 4 and 5), the plan method (section 10), the flow and flow-log templates, the new-adapter guide, the README; the changelog fragment.
- **Verified by:** `tools/lib/flow-executors.test.mjs` (the reuse with every reason when it is warm, each of fourteen conditions that alone forbids it, the limits of the flow, the
  smaller step that keeps the bigger step's model, the previous worker of a log with a fenced template and a stop); `flow-command.test.mjs` (a fresh worker, then the warm one, then a cold
  one past its context and its cache; the manual fallback); the adapters' own tests; the conformance suite on both presets and on broken copies (an adapter without the role; executors that
  offer none, a session that cannot be continued, one that cannot report, a start that drops the prompt); `flow-check.test.mjs` (the reuse limits); `npm test` (678 pass), `npm run lint`,
  `npm run typecheck`, `npm run docs:check`. `harness flow dispatch` on a scratch two-step flow printed both means of the session executor with the model mapped (`claude-haiku-5-5`, `low`).
- **Decisions / deviations from the plan:** (a) **The role is `logic` (required)**, as the task's verification asks ("an adapter without an executor" fails the suite). By design §1.4 a
  contract change that fails an existing adapter is major; no runtime adapter outside this repository exists yet (the adapters of a project's own repository arrive in the same `0.3.0`,
  task 3.4), so it ships in a minor of `0.x`, and the contract carries `"contract": 2`. The alternative is `logic-optional` with the framework's manual executor as the fallback: no
  adapter could break, but a runtime would never be made to say what it can do. **The owner decides this in the pull request** (D3). (b) The adapter returns means, data the orchestrator
  carries out, so the tools stay free of the runtime and need no process of their own; the prompt is a slot (`<prompt>`) that the tools fill with the command that prints it. (c) A
  step whose Model is a dash keeps the worker's model when it is reused, like a smaller step after a bigger one: a D0 decision `dispatch` names. (d) The prompt cache of Claude Code is
  counted as an hour (a subscription); a flow on an API key sets `reuseLimits.cacheMinutes` to 5. (e) The pause since the worker's last turn is read from the log's times; the context is
  given by the orchestrator (`--context`), read by the executor's `context` means after the step; unknown means a fresh worker.
- **Problems / blockers / findings:** **the probe was not run.** The task asks for a two-step flow run by the session executor with the second step warm. On the command line `claude -p`
  answered "OAuth session expired and could not be refreshed" (the owner signs in again; an agent does not), and it warned `unrecognized_model` for `claude-haiku-5-5` on Claude Code
  2.1.276, which the probe must confirm or the model mapping must change. Starting a worker session in the desktop app was refused by the session's permission check. `get_usage` of the
  desktop app reports an idle session's context as unavailable, so in the app a reused worker may be rare until the probe shows what an ended turn reports.
- **Next step:** the owner reviews the contract change of pull request #92 (decision (a)); then the probe: sign in the command line (`claude /login`) or allow a worker session, run a
  two-step scratch flow by `harness flow dispatch` (the session executor), and record whether step 2 is warm (`cache_read_input_tokens` of the second call against its input); then mark
  5.5 ✅ and go on with 5.6.
- **Verify with:** `npm test`, `npm run docs:check`, `node tools/harness.mjs adapter test adapters/runtime/claude-code`, `node tools/harness.mjs adapter test adapters/runtime/cursor`,
  `node --test tools/lib/flow-executors.test.mjs tools/lib/flow-command.test.mjs tests/conformance/conformance.test.mjs`.
