# 5.1 — The release order in a file of its own (`releases.md`)

**Status:** ✅ · **Agent:** C2 · **Size:** 5 SP

**The release order in a file of its own (`releases.md`)**: the order of development is today a section of the plan index ("Order of development"): `tools/lib/next-task.mjs` parses it, `check plan` (`orderProblems` in `tools/lib/plan.mjs`) checks its ids, and the plan method (`core/plan/README.md` sections 3 and 6, `index-template.md`), method section 6, the procedures `start-task` and `change-plan`, and the execution-order lines of the phases point at it. Move it into a file beside the index (the owner's decision of 2026-11-04: the index stays the one entry point and links to it): (1) a template in `core/plan/` with one table `Release | Status | Tasks, in order | Consumers | Notes` (status ⬜ planned · 🟡 developing · 🏷 `dev.N` cut · ✅ released) and a "Not scheduled" list; (2) an optional profile role `paths.releases`: a project that ships no versions has no such file and loses nothing, and without the role the tools read the section of the index as today; (3) `next-task.mjs` and `check plan` read the file; a row names tasks and issues only, and the check refuses a backlog item (`B-<n>`, task 3.21) and an id that exists nowhere; (4) the index gets a generated block between markers (the current release and its state, the next release, a link to `releases.md`, and to the flows index once 5.2 exists), and the plan method, method section 6, `start-task`, `change-plan`, the index template and the phases' execution-order lines say where the order lives; (5) a migration script of `0.3.0` moves the section of a project's index into the file when it is a table, and leaves an order written in prose with a message (the consuming project writes its order as arrows of phase numbers, which the tools cannot read), which the migration note turns into a required action; (6) this repository's index is migrated by the script. Verified by tests of the reading, of the check (a backlog item and an unknown id refused) and of the script (a table moved, prose left with its message, a second run changes nothing), by the session-start hook printing the same next task before and after the move on this repository, and by `npm run docs:check`.
