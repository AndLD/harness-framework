# 5.6 — Usage: read it, estimate each step, and gate the next one

**Status:** ⬜ · **Agent:** C2 · **Size:** 5 SP · **Needs:** 5.4, 5.5

**Usage: read it, estimate each step, and gate the next one**: (1) before each step the orchestrator reads the account's usage through the runtime adapter (the Claude Code desktop app reports the 5-hour and the weekly window in whole percent with their reset times; a runtime that cannot read it asks the owner); (2) it estimates the step in percent of a window by its SP, model, step kind and the subscription, from a table of coefficients in the runtime adapter (claude-code: Pro, Max 5x, Max 20x, and the API, where a cost replaces the limits; cursor: a mock); (3) if the current use plus the estimate times a safety factor passes the flow's `stopAt`, it waits for the reset or stops and tells the owner; `harness flow check` flags a step whose estimate does not fit one window, so it is split when planned, and the flows index shows each flow's estimate, so a flow can be sized against the weekly window before it starts; (4) measurement: the usage at the start and the end of a flow and before and after each step (the window percents with `resetsAt`, tokens when the runtime gives them, the model, the SP, the kind, and whether the worker started cold or warm) is appended to `flows/usage.jsonl` (tracked, shared by every flow), and a short line goes into the flow's log. Verified by tests of the estimate, of the gate (under, over, a reset in between) and of the sample writer, and by a probe where a step that does not fit waits for the reset.
