# 5.8 — Flows across repositories: one home repository and external ones

**Status:** ⬜ · **Agent:** C2 · **Size:** 3 SP · **Needs:** 5.4, 5.5

**Flows across repositories: one home repository and external ones**: a flow belongs to its home repository; optional `repos` rows name the external ones (an alias, the remote, the role such as consumer, the step kinds allowed there), and their local paths go in the ignored `harness-profile.local.json`, since they differ per machine. With the home repository only, the template leaves the Repo column out. In an external repository the orchestrator only starts a worker there (the executor of 5.5, in that folder); it never edits files there, the prompt runs under that repository's own entry file and approvals, and the authority of 5.3 covers the home repository's releases only. A step names the consumer's work by what it does ("take `0.2.0-dev.1`"), never by the consumer's task ids, which belong to its own plan. `harness flow status` checks an external step through the host (its pull requests, its lock file). Verified by tests of the rows, of the local paths and of the external done-checks (the host's command line as a parameter), and by the external step of 5.9.
