# 3.11 — A consumer has no instructions for taking a new version, and many will skip versions

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP · **Needs:** 3.7, 3.8 · **Log:** [3.11.log.md](./3.11.log.md)

**A consumer has no instructions for taking a new version, and many will skip versions**: a project that takes `0.1.0` and later `0.3.0` must know what changed for it in every version between; today only the changelog exists, which says what changed, not what a consumer must do, and the consuming project of the extraction got a migration task written by hand for it. (1) A **migration note** for every version, from the previous one: `migrations/<version>.md` (from `0.1.1` on), in a fixed shape: what changed for a consumer; the required actions, each with the check that proves it is done; the optional actions; how to verify. A version that needs nothing says so. Mechanical changes are not written as instructions: they are migration scripts (3.12); a note holds what needs judgment (for example: a project file that restates a changed rule; a choice the consumer makes). (2) The release procedure and `harness release` refuse a version without its note; the changelog entry of a version links its note. (3) Each note lists the **areas** the version touched, from a fixed list the framework keeps (for example: entry rules, plan format, procedures, review method, Git rules, adapter contract), derived by `harness release` from the diff of `core/`, `tools/` and the adapters between the two versions; the probes of a project are matched to them (3.15). (4) The note of `0.1.1`: what the scan of 3.7 means for a consumer (words to add to `productGeneric`, the exception of 3.8, the issue template). (5) The framework's README says how a consumer takes a version, also across several: the notes from its version to the target, in order. Needs 3.7 and 3.8 first (its first note describes them). Verified by `harness release --dry-run` failing without a note, by the note of `0.1.1`, and by the CORE scan. The owner's decision of 2026-11-03.
