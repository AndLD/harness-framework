# 3.15 — A migration is not checked for what it does to an agent

**Status:** ✅ · **Agent:** C2 · **Size:** 2 SP · **Needs:** 3.11 · **Log:** [3.15.log.md](./3.15.log.md)

**A migration is not checked for what it does to an agent**: a version can pass every check and still make agents read more, or leave a project document that restates a rule the version changed. The probes that measure this belong to each project (its bindings name and write them), so the framework cannot name them. (1) Each probe in a project's bindings names the areas it exercises, from the list of 3.11, and the bindings stub of the scaffold does so for its starting probes; (2) the procedure `update-framework` (4.4) reruns the probes whose areas meet the areas of the versions taken, compares their words read with the project's last review, and reports an area that no probe covers, then runs the framework's starting probe for it. Needs 3.11 first; 4.4 uses it. Verified by the scaffold's bindings stub, the CORE scan, and the procedure followed on a scratch project across a version that touches the plan format.
