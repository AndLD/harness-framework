# 3.16 — Reports from users are neither taken in nor sent upstream by any procedure

**Status:** ⬜ · **Agent:** C2 · **Size:** 6 SP · **Needs:** 3.13

**Reports from users are neither taken in nor sent upstream by any procedure**: the framework receives reports from its consumers as issues on its host, and a consumer finds defects of the framework while it takes a version, but no procedure handles either, and turning every report into a task would fill the plan with copies of one problem. (1) **Intake**, set by `reports.intake` in the profile file: `off` (the scaffold's default: no hook, no skill), `notify` (the session-start hook prints the open reports and those not yet triaged; the agent does not process them, and the owner starts the triage), `auto` (the agent triages before other work, at most `reports.triageLimit` reports a session; the rest wait). A local, ignored override file changes these switches at once, without a pull request, so the owner can pause intake when the flow breaks or reports flood in. This repository: `auto`, a limit of 3. (2) **The procedure `triage-reports`** never adds a report as a new task before it looks for the same or a close problem already recorded: in the open queue, its archive and the open tasks of the phases, the indexes first (title, area), then the candidates' files. The same problem: the report is added to that issue's `Reported:` and answered as a duplicate. Fixed already: answered with the version that has the fix; when the reporter's version has it, a regression, a new issue that links the old one. Close but different: a new issue that names the related one. Not a defect: answered and closed (for example an ordinary word, the rule of 3.8). A confirmed new defect: a new issue. Answers and closings on the host need the owner's approval. (3) **The procedure `report-upstream`** for a consuming project, set by `reports.upstream`: `off` (the default: the suspected defect is only noted in the task's log and the owner told, with no draft), `ask` (it searches the framework's existing reports for the same problem first, then drafts one from the issue template of 3.8 and posts it after the owner's approval) or `post`. (4) The host adapter gets an optional capability to list, search, create, comment on and close reports (GitHub: `gh`); a host without it keeps both switches `off`. (5) A switch that is on adds one line to the entry file's generated rules, pointing to its skill; a switch that is off adds nothing, so a project that uses neither pays no words for them. Needs 3.13 first. Verified by tests of the hook and the switches (the override included), by a triage on fixtures (a duplicate, a close one, one fixed already, a regression, a new one, more reports than the limit), by `report-upstream` on a fixture at `ask`, and by the CORE scan. The owner's decision of 2026-11-03.
