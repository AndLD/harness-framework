# 3.14 — A migration cannot be undone exactly

**Status:** ✅ · **Agent:** C2 · **Size:** 2 SP · **Needs:** 3.12 · **Log:** [3.14.log.md](./3.14.log.md)

**A migration cannot be undone exactly**: a migration changes files across the project (the vendored copy, `AGENTS.md`, the skills, the profile file, the lock, the hooks, the documents of 3.10 and 3.13), so a copy of a few folders cannot restore it. Undo through Git, with a check (the owner's decision of 2026-11-03): (1) `harness migrate` refuses to start with uncommitted changes or on the integration or production branch, and records the starting commit and version in the lock first; (2) it commits its own changes as one commit, and the agent's changes follow as separate commits; (3) `harness rollback` restores every file the migration changed or added to the recorded commit, and nothing else; (4) the migration test (3.12) migrates each released tag, rolls back, and requires an empty diff against the starting commit. No step is written to run backwards. Needs 3.12 first.
