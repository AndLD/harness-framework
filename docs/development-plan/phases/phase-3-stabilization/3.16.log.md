- **Branch:** `feature/3.16-reports` — done. It needs 3.13 (the queue it triages into); it branched from that task's branch while its pull request was open.
- **What was built:** (1) *Switches.* `reports.intake` (`off` default, `notify`, `auto`), `reports.triageLimit` (3) and `reports.upstream` (`off` default, `ask`, `post`) in the profile file's new `reports` role; a local, ignored `harness-profile.local.json` overrides them at once, checked value by value (`tools/lib/reports.mjs`); a host adapter without the `reports` role forces both switches off. This repository: `auto`, limit 3. (2) *Host.* The optional host role `reports` (the contract's table, the manifest schema): the GitHub adapter's `reports.mjs` lists, searches, shows, creates, comments on and closes reports with `gh` (a seam for tests) and finds the framework's slug from an address. (3) *Command.* `harness reports status|list [--untriaged]|show|search|candidates|plan|comment|close|create` (`tools/lib/reports-command.mjs`): `candidates` compares a report with the titles and areas of the open and archived issues and the open tasks (indexes first), `plan` prints what a verdict does (the same problem, a close one, fixed already, a regression by the reporter's version against `Fixed in:` of the archived issue, a new one, not a defect); what is said on the host needs `--approved` after the owner's approval; `--upstream` takes the framework's repository from the lock's source and follows `reports.upstream`. (4) *Procedures* `triage-reports` and `report-upstream`, with a new frontmatter key `when` (a role that must be set and not `off`): without it no skill is generated and no row is added to the entry file's reading map. (5) *Rules and hook.* A switch that is on adds one line to the entry file's Git rules block (`core/rules/reports/*.md`, appended by the tools, one line each for intake and upstream); the session-start hook prints the open reports and those not triaged yet (notify: "do not process them"; auto: the limit). The issue file gets an optional `Fixed in:` field.
- **Decisions / deviations from the plan:** the report lines are appended to the Git rules block by the tools and are not conditionals in `core/rules/git.md`: a `sync` is run by the tools of the version a project has, which render the new template and know no new flag, and the migration test (a project from each released tag takes this tree) failed on exactly that. The same test showed that such a sync writes the skill of every procedure of the tree, so the script of 0.2.0 removes the skills of procedures whose switch is off. "Not yet triaged" is "no `Reported:` line of an issue records it" (and no task text that cites it). The upstream draft has its own parts in the procedure and does not copy the host's issue template (it is not distributed).
