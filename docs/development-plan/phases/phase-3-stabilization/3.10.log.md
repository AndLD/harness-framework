### 2026-11-04 — phases are folders, tasks are files
- **Branch:** `feature/3.10-task-files` — done. It needs 3.12, and branched from 3.14's branch (which had 3.12 in) while that pull request was open.
- **What was built:** (1) *Layout.* `tools/lib/phase-files.mjs` reads a phase folder `phase-<n>-<slug>/`: `README.md` (the phase index, with the task table between `<!-- phase-tasks:start -->` and `<!-- phase-tasks:end -->`), `<id>.md` (title `# <id> — <title>`, a status line with `Status`, `Agent`, `Size`, optional `Needs` and `Log`, then the description), `<id>.log.md` and `log.md`; the one-file layout is read as before. (2) *Tools.* `harness plan summary` writes the phase index table as well as the plan index; `check plan` holds the layout (the size of the title is the sum of the task files, a status and a size in every task file, a marker in every open one, the log links resolve, the table is current); the session-start hook prints the newest "next step" across the phase log and the task logs by entry date (a tie goes to the later log, in task order) and the open tasks (id and title), and `nextTask` takes its tasks from the task files. `tools/lib/phase-split.mjs` splits a one-file phase: it writes the index and a file per task row, moves `work-logs/phase-<n>/<id>.md` to `<id>.log.md` and the work log to `log.md`, and rewrites every relative link of the repository to them (anchors kept), the links inside the moved text (made relative to its new place) and the full paths written in code spans. It is the migration script `migrations/0.2.0.mjs` (the open phases of a project; a folder and a finished phase are left alone, so it runs twice) and `harness plan split <phase>` (a phase by choice). (3) *Method and templates.* The phase template became `phase-index-template.md` plus `task-template.md`; method §6, the plan method (README and `phases.md`), `start-task`, `end-session`, `finish-phase`, the profile roles and the scaffold (the open-ended phase of a new project is a folder, with `log.md`) say so. (4) *This repository* split its open Phases 2, 3 and 4 (the finished Phase 1 stays one file).
- **Decisions / deviations from the plan:** a task row's whole text becomes the task file's description (its bold lead is the title), so nothing of it is lost; `Needs` is taken from a "Needs 3.5, 3.12 first" sentence when the description has one. A task log is linked from its task file only when it exists. The templates cannot show their own example links (the link checks resolve them), so they write them as code spans. The probe P2 of the consuming project cannot be run here.
