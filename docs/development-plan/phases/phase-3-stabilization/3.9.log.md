### 2026-11-03 — one reading of an open claim, and the next task by the order the plan says
- **Branch:** `feature/3.9-claim-ownership` — done. It started from `develop` (not from the branch of 3.3, which would be a second level of stacking); it touches `session-start.mjs` next to the one line that 3.3 changed.
- **What was built:**
  - **The claim rule.** Method §6 (claim before work, at the start of a session) and §7 (claim): a claim belongs to its session while that session works; a session that resumes a phase continues a claimed task when the task's log or the phase's work log records a pause or a "next step" that names it, or when the owner says so; otherwise it asks and starts nothing. The claim rule of the entry file (`core/rules/git.md`) cites it, and step 1 of `start-task` says the same.
  - **Which task is next.** Method §6 and step 2 of `start-task`: the phase's execution order, and the order of development of the plan index when the phase points there; the table's order only when neither exists.
  - **The hook.** `tools/lib/next-task.mjs` (`readPhases`, `phaseSequence`, `orderOfDevelopment`, `nextTask`) reads the phase files and the plan index as strings; `session-start.mjs` prints `Next task: <id> <title> (<file>), by the <order of development | execution order | table>` when no phase is in progress and the plan has a task not started. The index's order counts the tasks column of its table only (the first holds versions) and expands "Phase N" into that phase's tasks; tasks the order does not name follow it.
- **Decisions / deviations from the plan:**
  - The hook prints the next task only when no phase is in progress (as the task says), and says to check for an open pull request first, since it reads files and does not ask the host.
  - A phase whose line names task ids puts them first, in that order, and the rest of its table after them.
