# 6.3 — Quiet variants of the stack's commands (lint, typecheck, test, coverage, format)

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP

**The commands of a project's own stack are the other half of the output.** Each stack adapter gives, next to its commands, a **quiet variant** (a role of the adapter, filled in the profile): the same check, with the output reduced to failures and a summary (for a test runner a reporter that prints only failing tests and a total; for a linter only the findings; for coverage only the figure and the files below the gate). The quality gates run by the hooks and by the agents' procedures use the quiet variant; the plain command stays for a person. The adapter contract names the role, the conformance suite checks that every preset fills it, and a project's own adapter (`harness-adapters/`) may fill it or say that it has none.

- Core stays neutral: the procedures say "the quiet variant of the quality gate" by its profile role and name no tool.
- A project that has no quiet variant keeps working: the hook caps and files the output (6.2).

**For consumers too:** the roles are in the profile template that `harness init` writes; an existing project gets them with `harness sync` and its migration note (which role to fill and how), and the take by a consumer measures the fall.

**Verified by:** the conformance suite on the presets and on a deliberately broken copy without the role; tests of the profile and of the hook's choice between the quiet and the plain variant; `harness check all` passes; the audit of 6.1 on a test and lint run before and after; the migration note exists.
