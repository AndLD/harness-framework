# 6.1 — `harness flow audit`: where the tokens of a flow went, and the baseline

**Status:** ⬜ · **Agent:** C2 · **Size:** 5 SP

**Measure before cutting.** `harness flow audit <n>` reads the transcripts of the sessions of a flow (its orchestrator and its workers) and prints where the tokens went: by tool (shell, read, edit, the app's tools), by command (the first words of a shell command, so a commit with its hook output and a `git show` of a file are visible), by step, and the agent's own output apart from tool results; the largest single results are listed with the command that made them. It counts tokens by the usage the runtime reports when it reports them, else characters divided by four, and says which. Two numbers are kept apart: what **entered** the context and the **peak** context of a session, since everything is read again on each turn.

- **A role of the runtime adapter** (`transcripts`): where the sessions of a flow are and how to read them (the Claude Code adapter reads its session files, matching the workers by the ids that the flow log names). Core stays neutral and holds only the report; a runtime without the role says that the audit cannot run.
- **For consumers too:** the tool is distributed, the role is in the adapter's manifest, and a consumer's flows are audited the same way.
- **The baseline:** a report of flow 1, written as an entry of the phase log: totals, the top sinks by command, and the figure that the other tasks are judged by (the aim of the phase, a third fewer tool-result tokens on a comparable step, unless the owner names another figure in that entry). It reuses and replaces the one-off script of the discussion of 2026-11-05.
- `harness flow calibrate` may take the per-step attribution later; this task only prints.

**Verified by:** unit tests with a fixture transcript (known sizes by tool and by command, the largest results, the two kinds of token count, a transcript with no usage); the conformance suite of the runtime adapter with the new role; `harness check all` and the CORE scan pass; the baseline entry in the phase log, whose totals match a hand count of the fixture and of one real step; the tool is in `framework.json` and a consumer fixture of the migration test finds it.
