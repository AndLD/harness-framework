### 2026-11-07 — quiet by default
- **Branch:** `feature/6.2-quiet-output` — done.
- **What was built:** (1) `tools/lib/output.mjs`: the output file of a step, the lines kept of a failed run (the lines that look like failures, else the last ones, capped, the rest counted), and the new profile value `output.maxLines` (default 40). (2) `harness check all` prints the problems and one line (`N checks passed`); `harness check <name>` prints its first message on a pass; `--verbose` prints everything as before; the project checks (`checks.project`) write to a file and print its path and failing lines on a failure. (3) `harness gate` (the pre-push hook) runs each step with its output in a file, prints a header and `pre-push: passed (N step(s))`, and on a failure the file's path and its failing lines; `--verbose` restores the live output. (4) `harness flow dispatch --brief`.
- **Measured (the audit's way, on this branch's own push):** the gate of the push of this branch printed 212,567 characters (about 53k tokens) with `--verbose` (the old behaviour) and 122 characters quiet; the same exit codes. `harness check all` fell from 1,365 to 38 characters.
- **Decisions / deviations from the plan:** (a) **The migration note is not written here**: the note of a version is written when the release is cut, from the changelog fragments (`migrations/README.md`), so the fragment `6.2-quiet-output` says what a script must do (use `--verbose`); 6.8 holds the consumer fixture. (b) **The runtime hooks** (`guard-*`, `format-edited`, the session start) print nothing or a short context already (the session start about 950 characters), so they are unchanged; the long output of a hook was the gate's. (c) **`flow dispatch`** keeps its text by default; `--brief` drops the groups for reading the report, the context and the usage (5.9k to 3.4k characters). `flow status`, `next`, `gate` and `plan summary` are short already (one to 16 lines) and unchanged. (d) The Git hooks need no change: they call the gate and the guard.
- **Problems / blockers / findings:** the biggest sink was the gate's inherited output (the whole test run on every push); the failing-lines heuristic is a pattern, so a runner with other words for a failure falls back to the last lines.
- **Next step:** 6.3, quiet variants of the stack's commands.
- **Verify with:** `npm test`, `npm run docs:check`, `node --test tools/lib/output.test.mjs tools/lib/gate.test.mjs`.
