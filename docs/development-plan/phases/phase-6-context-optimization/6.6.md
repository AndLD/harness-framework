# 6.6 — Delegating verbose reading to a subagent

**Status:** ✅ · **Agent:** C2 · **Size:** 2 SP · **Needs:** 6.1

**Keep the verbose work out of the context that makes the decisions.** The procedures and the standard step prompts say when an agent hands reading to a subagent (the executor `subagent`, which the plan method already allows for a short analysis): a large log, a long diff, the output of a long test run, a research of sources. The subagent returns a **capped summary** (a few lines, the evidence as pointers: file and line, command, commit), and the agent keeps the decision. The same text says what is **never** delegated: a decision, a write, a merge, the reading that a procedure requires in full. `harness flow prompt` adds the paragraph to the prompts of the step kinds where it applies, and the runtime adapter says how it starts a subagent.

**For consumers too:** the procedures and prompts are core and distributed; the runtime part is a role of the adapter.

**Verified by:** tests of the prompts (the paragraph appears for the kinds that need it and not for others); `harness check all` passes; a dry run of a step that reads a large log through a subagent, whose context cost is measured by the audit of 6.1 against reading it directly; the migration note exists.
