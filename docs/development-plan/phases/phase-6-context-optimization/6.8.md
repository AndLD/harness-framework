# 6.8 — Consumers take the phase, and the fall is measured

**Status:** ⬜ · **Agent:** C2 · **Size:** 3 SP · **Needs:** 6.2, 6.3, 6.4, 6.5, 6.6

**Delivery is part of the phase, and this task proves it.** It checks that everything of 6.1 to 6.6 (and 6.7 when it builds something) reaches a project that uses the framework:

- `framework.json` lists the new tools, procedures, templates and adapter roles in `distributable`; `harness init` gives a new project the quiet hooks, the commands' quiet variants in its profile and the flow settings; `harness sync` and `harness migrate` bring an existing project to them, with a migration note per version that says what the consumer must do (the quiet commands to set, the procedures whose wording changed, the new flow setting) and a probe area in the notes.
- A **consumer fixture** of the migration test takes the version and shows quiet hooks, the new roles and the flow settings in place, and that a project that does nothing keeps working (the defaults are safe).
- **The first consumer's take** (the project the framework was extracted from) is run as a flow step; the audit of 6.1 compares a comparable step before and after against the baseline, and the result, with the aim of the phase (a fall of tool-result tokens, no rise in failed checks or deviations), is written in the phase log.

**Verified by:** the fixture test; the migration notes of each version in the phase; the audit comparison in the phase log; `harness check all` passes; the take by the consumer is merged by that repository's owner, as its rules say.
