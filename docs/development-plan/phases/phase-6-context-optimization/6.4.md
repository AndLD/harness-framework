# 6.4 — Output budgets for agents and a short schema for step reports

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP

**What an agent puts into its own context is a rule, not a habit.** The core procedures and the step prompts state:

- **Output budgets:** read with a filter instead of a whole output (`--jq` on the host's command line, `--stat` and a path for a diff, the tail of a log, an offset and a limit for a file); a whole file is read only where a procedure says so (the migration note before a cut is the one such place); a command that may print a lot is run with its quiet variant (6.2, 6.3) or its output is capped.
- **A schema for the step report** (status, ids done, pull requests, decisions with their options and level, deviations, recommendations last) with a cap on its length, and a place for what does not fit (the task's log, a file the report links), so an orchestrator reads a report whole without paying for prose.
- **Short closing messages and bodies:** the final message of a session, a pull request body and a commit message say what changed, what was verified and what was not, in a few lines; long text goes in a file of the plan and the message links it.

The procedures that change: `run-flow`, the standard step prompts, `start-task`, `open-pull-request`, `end-session`, and the method (section 4, the definition of done, where it says what a report holds). A change of what a procedure means: a flow that runs this task decides it as the kind `contract.change` (the procedure `run-flow`, I-20), else it needs the owner's approval in the pull request; a change of the meaning of a core rule stays the owner's.

**For consumers too:** the procedures and the step prompts are core and distributed; the packaged skills are regenerated by `harness sync`; the migration note lists the procedures whose wording changed.

**Verified by:** `harness check all` (the CORE scan and the links), a check that a step report of a fixture follows the schema and the cap, a dry run of a flow step with the new prompts whose report and commands are measured by the audit of 6.1 against the baseline, and the owner's approval recorded in the pull request.
