### 2026-11-07 — quiet variants of the stack's commands
- **Branch:** `feature/6.3-quiet-stack-commands` — done.
- **What was built:** (1) the profile roles `commands.lintQuiet`, `typecheckQuiet`, `formatQuiet`, `testQuiet`, `testCoverageQuiet` in the schema; (2) the optional stack-adapter role `quiet-commands` (manifest schema, `core/contracts/stack.md`), filled by `node-ts` and `python` with their quiet commands in `defaults.commands` (a quiet role only where the stack defaults the plain command: `node-ts` has lint, test and testCoverage, `python` also typecheck); (3) `tools/lib/quiet-commands.mjs`: a quiet role not set is the plain command, so the procedures (`open-pull-request`, `end-session`, `release`, `update-framework`) cite `{{commands.lintQuiet}}` and `{{commands.testCoverageQuiet}}` and a project with none keeps working; (4) a `quiet: { args }` variant on the test steps of the node-ts gate plan and on every tool step of the python plan, which the gate runs unless `--verbose`; (5) a conformance check on the role (skips without it; fails when a quiet command is missing or equals the plain one); (6) the framework's own profile sets its quiet commands.
- **Measured:** this repository's test run prints 212,044 characters with `npm test` and 857 with the quiet variant (`--test-reporter=dot`), about 53k tokens to 0.2k; lint prints 120 characters either way when it passes (Prettier's check is quiet on a pass). The node-ts and python options (Jest's `summary` reporter, `ruff --quiet`, `pytest -q`) are written from their documentation and tested for the arguments they produce, not run against a Jest or pytest project here: the consumer's take (6.8) is their proof.
- **Decisions / deviations from the plan:** (a) **The recommendation of 6.2 (the failing-lines pattern as a setting of the stack adapter) was not taken**: with the quiet variants the output of a passing run is a total, and a failure's lines are the runner's own; the generic pattern only serves the fallback for a project without quiet variants, where a stack-specific pattern would add a role for little. (b) **No migration note**, as in 6.2: it is written at the cut from the changelog fragment, which says which roles to set. (c) The consumer fixture of the migration test is 6.8's. (d) `README`'s `check all` row is unchanged; the roles are in the contract and the schema.
- **Problems / blockers / findings:** the template engine drops a line whose placeholder has no value, so a procedure citing `commands.lintQuiet` would lose its line in a project without it; `withQuietDefaults` fills the plain command before rendering, and the "needs the profile roles" check reads the filled profile.
- **Next step:** 6.4, output budgets for agents and the short step-report schema.
