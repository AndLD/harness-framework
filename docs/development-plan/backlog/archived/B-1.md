# B-1 — A profile switch for the probes of a migration: `auto`, `ask` (the default) or `disabled`

**Status:** ✅ · **Agent:** C1 · **Size:** 5 SP · **Area:** procedures · **Source:** report — [GitHub issue 65](https://github.com/AndLD/harness-framework/issues/65) · **Formerly:** I-6 · **Log:** [B-1.log.md](./B-1.log.md)

**A profile switch for the probes of a migration: `auto`, `ask` (the default) or `disabled`**: the procedure `update-framework` tells a project to run every probe whose areas the versions touched, each as a session of its own (nine in the project that reported it, 5,000 to 12,000 words each), for every release, and the framework gives the owner no way to say "not for this release". The owner asks for a profile value (a key of the profile schema, for example `probes.run`, with a default, overridable by `harness-profile.local.json`) that the migration relies on: `auto` runs the probes `migrate` lists and reports what each read against the last review, `ask` (the default) asks and runs them only on a yes (a run with no terminal behaves as `disabled`), `disabled` only advises, at the end of the output, to run them. `auto` needs a runner (one read-only agent process per probe in the project's folder, recording the files and words read), which no command is yet; the value can ship first with `auto` and `ask` falling back to the advice. The procedure says that running the probes is the project's choice, by the mode, and the note of the version that adds it says how a project chooses. An improvement, not a defect: it does not block `0.2.0`. Reported by AndLD/bot-rts: [issue 65](https://github.com/AndLD/harness-framework/issues/65).

A request for something new, not a defect: it was issue I-6 of the issue queue until task 3.20 added the backlog, and it moved here as `B-1` (`Formerly: I-6`). It is scheduled for `0.2.0-dev.3` in the order of development of the plan index.
