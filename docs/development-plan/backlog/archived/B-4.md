# B-4 — A security policy file, here and in the scaffold

**Status:** Promoted · **Promoted to:** 2.12 · **Size:** 1 SP · **Area:** templates and scaffold · **Source:** agent · **Formerly:** I-44

The first security review (the [first security review](../../../quality-reviews/security/2026-11-08.md), finding S-20261108-10, probe S3-020) found no `SECURITY.md`, so a person who finds a weakness in a framework that other projects run has no written way to report it in private. The owner turned on the host's private vulnerability reporting on 2026-11-08; this item is the files.

What is wanted: a `SECURITY.md` of this repository (the versions that get fixes, how to report in private, what happens to a report, and that the issue queue is public), and a template of it in the scaffold, so that every project has one; `check security` no longer reports S3-020.

Filed as I-44 on 2026-11-08; the owner moved it here the same day (a feature belongs to the backlog) and promoted it into Phase 2, so that it stays in `0.6.0` as step 7e of flow 4.
