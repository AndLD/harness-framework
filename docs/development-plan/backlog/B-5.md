# B-5 — A host-side gate between an agent and a merge to production

**Status:** Proposed · **Size:** 3 SP · **Area:** host adapters · **Source:** agent · **Formerly:** I-45

The first security review (the [first security review](../../quality-reviews/security/2026-11-08.md), finding S-20261108-03, high) found that agents act with the owner's credential, and that the rules forbidding a merge to the production branch are held by the agent's own hooks: one mistaken or manipulated session can do what the owner can on the repository.

What is wanted, in this order:

1. A separate identity for agents (a second account of the host or an app), limited to the repository and without the administrator's role. The owner creates it; the framework says how, and how the agent runtime receives its token. Without it the next two parts would block the owner's own merges, since the host never lets an author approve their own pull request.
2. An ownership file over the CI definitions, the hooks and the rules, generated from the profile.
3. The owner's approval required on the production branch, set by `harness host protect` when the profile says so (a new role, off by default).

Filed as I-45 on 2026-11-08; the owner moved it here the same day (a feature belongs to the backlog). It waits for the owner to create the agents' identity and to promote it.
