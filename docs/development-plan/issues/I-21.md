# I-21 — A flow cannot ask its workers for plain commands, which a strict permission mode would let through

**Status:** 🟡 · **Agent:** C2 · **Size:** 1 SP · **Area:** procedures · **Reported:** —

**A flow cannot ask its workers for plain commands**: the worker of step 2 of flow 2, a session in a permission mode that asks for what it cannot check before it runs, asked the owner for almost every command, though the flow's tools were allow rules of the project: it wrote files by heredocs with braces and quotes, nested commands (`$(…)`), subshells and chains of commands, which such a mode asks for whatever the rules say. The owner set the flow's mode to `auto` (the log of flow 2, 2026-11-07 11:00), and asked (2026-11-07) for a switch, a setting of the flow, between plain commands and commands as the worker writes them, with heredocs allowed for now. The fix: a setting `commands` of the flow, `any` (the default, as before) or `plain`, which adds to the prompt of each step a section that asks for files written by the runtime's edit and write tools, no nested commands, subshells or redirections into files, and independent commands as parallel calls of one message. Found by the orchestrator of flow 2.
