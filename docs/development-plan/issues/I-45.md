# I-45 — No host-side gate stands between an agent and a merge to production

**Status:** ⬜ · **Agent:** C3 · **Size:** 3 SP · **Area:** host adapters · **Reported:** the [first security review](../../quality-reviews/security/2026-11-08.md), finding S-20261108-03

The first security review found that agents act with the owner's credential, and that the rules forbidding a merge to the production branch are held by the agent's own hooks: one mistaken or manipulated session can do what the owner can. The fix has three parts, in this order:

1. **A separate identity for agents** (a second account of the host or an app), limited to the repository and without the administrator's role. It is the owner's to create; the framework says how (the host adapter's guide, and how the agent runtime receives the token). Without it the next two parts would block the owner's own merges, since the host never lets an author approve their own pull request.
2. **An ownership file** (`CODEOWNERS` on the host of the preset) over the CI definitions, the hooks and the rules, generated from the profile.
3. **The owner's approval required on the production branch**, set in the ruleset by `harness host protect` when the profile says so (a new role, off by default).

**Done when:** the host adapter writes the ownership file and the approval rule from the profile, with tests; the guide says how an owner sets up the agents' identity; the changelog has a fragment; and the owner has decided when this repository turns it on.

**Verify with:** `node --test`, `node tools/harness.mjs check all`, and `harness host protect` against a scratch repository.
