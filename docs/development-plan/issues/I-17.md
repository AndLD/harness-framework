# I-17 — Pushing the tag of a release from the branch of the work fails the migration tests, and the procedure `release` does not say from which branch to push it

**Status:** ⬜ · **Agent:** C1 · **Size:** 1 SP · **Area:** procedures · **Reported:** —

**Pushing the tag of a release from the branch of the work fails the migration tests, and the procedure `release` does not say from which branch to push it**: when flow 1 tagged `v0.3.0` on the merge commit of the release pull request, the pre-push hook ran the framework's tests on the branch that was checked out, a branch of `develop` whose version was still `0.2.0`; two migration tests, which bootstrap a project from each released tag and take the current tree, took `v0.3.0` (now a local tag) to `0.2.0`, a downgrade, and failed, so the push of the tag was refused. The same push from a local branch at the merge commit (the tree of `main`, version `0.3.0`) passed. The procedure `release` says to tag the release on the production branch and to merge the production branch back into the integration branch, and does not say from where to push the tag; a fix is a sentence in the procedure and the releasing guide: push the tag of a release from a branch at the merge commit, before the merge back (and the same for a hotfix), with the reason, and a check that the tests name the tag they bootstrap from in their failure message. Found by the orchestrator of flow 1.
