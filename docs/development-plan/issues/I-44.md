# I-44 — There is no security policy file, here or in the scaffold

**Status:** ⬜ · **Agent:** C2 · **Size:** 1 SP · **Area:** templates and scaffold · **Reported:** the [first security review](../../quality-reviews/security/2026-11-08.md), finding S-20261108-10 (probe S3-020)

The first security review found no `SECURITY.md`, so a person who finds a weakness in a framework that other projects run has no written way to report it in private. The host's private vulnerability reporting is a setting of the owner's; this issue is the files.

- A `SECURITY.md` of this repository: the versions that get fixes, how to report in private (the host's private reporting), what happens to a report, and that the issue queue is public.
- A template of it in the scaffold (`core/templates/scaffold/`), written by the bootstrap, with the project's values as roles of the profile where they vary; the host adapter names how its private reporting is turned on.
- The probe S3-020 of `check security` passes here.

**Done when:** both files exist, a test holds the scaffold's output, `check security` no longer reports S3-020 for the file, and the changelog has a fragment with what a project does.

**Verify with:** `node --test`, `node tools/harness.mjs check all`, `node tools/harness.mjs check security`, and a scratch project from `harness init`.
