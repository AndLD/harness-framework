# I-9 — A condition inside a line (`{{#if role}}…{{/if}}`) is left unrendered in the generated skills

**Status:** 🟡 · **Agent:** C1 · **Size:** 2 SP · **Area:** procedures · **Reported:** —

**A condition inside a line is left unrendered in the generated skills**: the template engine (`tools/lib/render.mjs`) knows the blocks
`{{#if …}}`, `{{#unless …}}` and `{{#each …}}` only when each tag stands on a line of its own. A tag inside a line is not a placeholder either (its
path does not match), so it is copied as it is: `core/procedures/change-plan.md` writes `{{#if documents.planMethod}}: the [plan method](…) …{{/if}}`
in its first paragraph, and `.claude/skills/change-plan/SKILL.md` ships the raw `{{#if documents.planMethod}}` and `{{/if}}`; the skills `end-session`
(`{{#if host.autoMerge}}`) and `triage-reports` (`{{#if paths.backlog}}`) have the same leftover. A project whose profile leaves the role out gets
the text the condition was meant to hide, and the procedure's check (`neededRoles` in `tools/lib/procedures.mjs`) counts the role inside such a
condition as required. Found on 2026-11-04 while building task 5.3: a probe of the new procedure `run-flow` saw the raw tag in its generated skill;
`run-flow` was rewritten without it, and nothing checks for leftovers. A fix renders a condition inside a line (the text between the tags kept or
left out, the rest of the line kept), treats a role inside it as optional, and refuses a tag it cannot render; it is verified by a test that plants
an inline condition and sees it rendered, and by no `{{` left in any `.claude/skills/*/SKILL.md` after `npm run harness -- sync --local`.
