# I-34 — The bootstrap and the adoption write the settings file without the formatter's message

**Status:** ⬜ · **Agent:** C1 · **Size:** 1 SP · **Area:** bootstrap and sync · **Reported:** —

**The bootstrap and the adoption write the settings file without the formatter's message**: I-26 made `harness plan-write on` and `off` say to run the project's formatter on `.claude/settings.json`, whose form `JSON.stringify(…, null, 2)` a formatter such as Prettier rejects; the bootstrap (`scaffold.mjs`) and the adoption (`adoption.mjs`) write the same file in the same form and say nothing, so a project whose lint checks formatting fails its first lint after them. Found by the worker of I-26 (flow 3, step 8a). A fix: the bootstrap's and the adoption's messages name the file and say to run the project's formatter on it, as `plan-write` does; verified by tests of both messages.
