# I-38 — The session start carries the text of users' reports, and no test plants a payload

**Status:** ⬜ · **Agent:** C2 · **Size:** 2 SP · **Area:** procedures · **Reported:** the [first security review](../../quality-reviews/security/2026-11-08.md), findings S-20261108-01 and S-20261108-02

The first security review (task 2.4) found that the context added at the start of a session holds text that anyone can write on the public repository (S-01, high), and the rule `sec.outside-text` (task 2.10) now says such text is data. No test shows that an agent keeps to the rule (S-02: "a planted payload as a test").

- The session start gives the counts and the numbers of the open reports only (`tools/lib/reports.mjs` and the hook that prints them); the text of a report is read when a triage asks for it.
- A test plants an instruction in a report's text and shows that the session start does not print it; the procedure `triage-reports` quotes it as data.

**Done when:** no outsider's text reaches the context of the session start, the test holds it, and the changelog has a fragment.

**Verify with:** `node --test`, `node tools/harness.mjs check all`, and the session start run on a repository with a report whose title holds an instruction.
