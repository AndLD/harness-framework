# I-32 — `harness flow audit` misses the command-line workers of a flow

**Status:** ⬜ · **Agent:** C1 · **Size:** 1 SP · **Area:** checks · **Reported:** —

**`harness flow audit` misses the command-line workers of a flow**: the measurement of 6.9 (flow 3, step 9c) found that `harness flow audit 3` reads 2 of the 12 workers of flow 3: the finder of the workers (`workersOfLog`) reads a `local_…` session id or a "`claude -p` named …" name from the "step started" entries, but a command-line worker's session id is known only when it ends and is logged in its "step ended" entry, and its transcript lies under the folder of its worktree; flow 2's take is missed the same way. The measurement was done by a one-off script. A fix: the finder also reads the worker's id from the "step ended" entry (the line `Worker: cli <id>`), and finds a transcript by its id in any project folder of the runtime; and a reused session is split by step with the turns' times and the log's step entries; verified by a test on a log with session and command-line workers.
