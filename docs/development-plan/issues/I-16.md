# I-16 — The notes of a development version and the migration say too little: the final note is not printed on a development-only path, a check is false after the next version, and the arrows action has no answer for phases no release holds

**Status:** ⬜ · **Agent:** C1 · **Size:** 2 SP · **Area:** bootstrap and sync · **Reported:** —

**The notes of a development version and the migration say too little**: the second take of a development version by the consumer (step 1d of flow 1) found four gaps in what the notes say, none of which blocks a take. (1) `harness migrate` prints the notes of the versions between the two and leaves out the final note when only development versions lie between, though the note of `0.3.0-dev.2` sends the reader to `0.3.0.md`. (2) The required action 1 of the note of `0.3.0-dev.1` checks `migrations.version` is `0.3.0-dev.1`, which is false when the same jump goes on to `0.3.0-dev.2`: a check of a development note should name the lock of the version it is the target of, and say it is a check of that take only. (3) The required action about an order of phases written as arrows says to name the phases as "Phase N" in the release that holds them, and does not say what to do when no release holds them (a consumer's history); it should say to leave the order as text in "Notes". (4) The status 🏷 on a release whose development version is tagged upstream: the script says only the owner knows, and the notes do not say the status is set by hand; one sentence in the notes settles it. A fix is the wording of the notes and the print of `migrate`, with a test of the print. Found by the worker of step 1d of flow 1.
