# I-26 — `harness plan-write on` writes a settings file that the project's formatter rejects

**Status:** ✅ · **Agent:** C1 · **Size:** 1 SP · **Area:** runtime adapters · **Reported:** —

**`harness plan-write on` writes a settings file that the project's formatter rejects**: the Claude Code preset writes `.claude/settings.json` with `JSON.stringify(…, null, 2)` (`adapters/runtime/claude-code/plan-write.mjs`), which puts every entry of an array on a line of its own, while Prettier keeps a short array on one line; in a project whose lint checks the formatting, `npm run lint` fails right after the action, and the note's check (`plan-write state`) does not see it. Found by the take of `0.4.0` in AndLD/bot-rts (#303), whose worker ran `prettier --write` on the file before committing. The bootstrap's and the adoption's writes of the same file (`scaffold.mjs`, `adoption.mjs`) use the same form. A fix: the write keeps the formatting a formatter gives (short arrays on one line, as Prettier prints them at the project's width), or the action's message and the note say to run the project's formatter on the file; verified by a test that writes the settings and compares them with the formatted form.
