### 2026-11-07 — the hooks use the tools of the tree that runs them
- **Branch:** `bugfix/I-19-worktree-hook` — from `develop`, by the worker of step 5 of flow 2.
- **What was done:** `tools/git-hooks/pre-push` and `pre-commit` still find `harness.mjs` beside themselves, but when the hook runs from another tree than the one `core.hooksPath` names (a linked worktree), and that tree holds the same file at the same path below its top folder, they use it. A project whose hooks live elsewhere, or a worktree without its own copy, is unchanged. A test in `git-guards.test.mjs` installs the hooks in a main checkout and runs both from a linked worktree whose tools differ.
- **Decisions / deviations from the plan:** the issue proposed resolving `harness.mjs` from the top folder; that would break a project whose framework is vendored under another path, so the path of the hook below the main checkout is replayed below the worktree instead. The paths are compared physically (`pwd -P`), since Git reports real paths.
