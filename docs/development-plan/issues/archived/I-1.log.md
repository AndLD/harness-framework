### 2026-11-04 — the tests are not distributed
- **Branch:** `bugfix/I-1-vendored-tests` — done.
- **Reproduced:** a scratch project made by `harness init` with one stack (`node-ts`) and one runtime (`claude-code`), running `node --test` on the vendored `tools/lib`, `tools/runtime-hooks` and `tools/` tests: 20 of 428 fail (the ones that read the framework's own profile file, the ones that expect every preset, the bindings stub and the procedures of the framework's own tree).
- **Fix:** the second of the two ways the issue offered. The framework's tests are not part of what a project receives: `framework.json` has `excluded` (`[".test.mjs"]`), the list of file name endings that `selectFiles` leaves out. Making each test skip would have kept ~200 files in every project for tests that nothing in a project runs, and the next test would fail the same way. The next `sync` removes the test files from `harness/` (a sync replaces the folder).
- **Decisions:** the adapters' own tests are left out too; `harness adapter test` (the conformance suite of a new adapter) is code of `tools/lib`, not a test file, so it still ships.
- **Next step:** the migration note of `0.2.0-dev.3`.
- **Verify with:** sync a scratch project and run `find harness -name '*.test.mjs'`: it prints nothing.
