# I-24 — The tests fail on the tree that `harness release` leaves before its commit

**Status:** ✅ · **Agent:** C1 · **Size:** 1 SP · **Area:** checks · **Reported:** —

**The tests fail on the tree that `harness release` leaves before its commit**: `harness release` deletes the changelog fragments of `changelog.d/` and writes the changelog, and leaves the change uncommitted; `tests/harness-budget.test.mjs` then fails, because `measureReview` (`tools/lib/review-measure.mjs`) reads the tracked files and some of them are gone from the work tree. The procedure `release` says to commit the version, but not that the checks run only after the commit, so a worker that runs `test:coverage` first sees a red test that is not a defect of the version. Found by the worker of step 7d of flow 2. A fix: `measureReview` skips a tracked file that the work tree no longer has (or reads what the work tree holds), with a test that deletes a tracked file and measures; verified by `npm test` on the tree that `harness release` leaves.
