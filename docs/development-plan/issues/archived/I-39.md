# I-39 — The actions of the generated workflows are pinned to tags

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP · **Area:** host adapters · **Log:** [I-39.log.md](./I-39.log.md) · **Reported:** the [first security review](../../../quality-reviews/security/2026-11-08.md), finding S-20261108-06 (probe S2-004)

`check security` finds 8 actions pinned to tags in `.github/workflows/ci.yml` and 2 in `release.yml`; they come from `adapters/host/github/templates/` and the stacks' `ci-jobs.mjs`. A moved tag runs someone else's code in CI, and `release.yml` holds a write token. The orchestrator of flow 4 decided the pins on 2026-11-08 (D3, its log), and the owner deferred the rule `sec.pinned-actions` to come with them (2026-11-08, "First two; pins later").

- Pin every action of the templates and the stacks' jobs to a full commit, with its version in a comment, and say in the migration note how a project keeps the pins current.
- Propose the rule `sec.pinned-actions` of core again, with its check, for the owner's approval in the pull request.
- Then set `checks.security` to true in the profile, as the finding orders.

**Done when:** `check security` finds no action pinned to a tag here and in a generated project, the rule is approved or dropped by the owner, and the changelog has a fragment with the project's action.

**Verify with:** `node --test`, `node tools/harness.mjs check all`, `node tools/harness.mjs check security`, and `harness sync` on a scratch project.
