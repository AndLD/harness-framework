# I-12 — The migration of `0.3.0` writes prose into the release table's id column, leaves a skipped release as the next one, and leaves a prose order of phases without a message

**Status:** ✅ · **Agent:** C1 · **Size:** 3 SP · **Area:** bootstrap and sync · **Reported:** — · **Log:** [I-12.log.md](./I-12.log.md)

**The migration of `0.3.0` writes prose into the release table's id column, leaves a skipped release as the next one, and leaves a prose order of phases without a message**: the first take of a development version by a consumer (`0.3.0-dev.1` taken by AndLD/bot-rts, step 1a of flow 1) showed three faults in the script `migrations/0.3.0.mjs`. (1) It moved the old table of the section "Order of development" into the releases file as it stood, so the cell with prose (`17.18`, `12.7`, `12.5`, `12.6` and "Phase 12" among words) became the column "Tasks, in order", which the tools read as ids and refuse or misread. (2) A release that the consumer had skipped on purpose (`0.1.2`) stayed ⬜ in the new table, so the plan index said "Next: 0.1.2", and no status says "skipped". (3) The consumer's order of phases written as arrows (`0 → 1 → … → 17 → 10`) was left in Notes with no message, so the tools no longer read it and nothing told the consumer so; the migration note promises a message for a prose order. The consumer repaired the table by hand. A fix reproduces the three cases in the migration test (a table with prose in the task column, a skipped release, an arrow order beside the table), writes only ids the tools can read into the id column (keeping the prose in Notes), leaves a skipped release out of "next" with a stated rule (a status or a note the tools understand, written in the releases template), and prints the message for a prose order that the note promises. The migration of the previous versions is not touched. Found by the worker of step 1a of flow 1.
