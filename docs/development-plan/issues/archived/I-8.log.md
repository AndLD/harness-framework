### 2026-11-04 — the gate and the pre-push hook start their steps without the Git variables of the hook
- **Branch:** `bugfix/I-8-gate-git-env` — done.
- **What was built:** `REPOSITORY_ENV` (the list of `git rev-parse --local-env-vars`) and `withoutRepositoryEnv` in `gate.mjs`; `runGate` takes an `env` seam (the process's by default) and runs every step, and the project's preparation, without those variables. The pre-push hook unsets them (`unset $(git rev-parse --local-env-vars)`) after the guard, before the project's setup script and the gate; from the top folder Git finds the repository by itself.
- **Decisions / deviations from the plan:** (1) The fix is in the gate and the hook, not in each test helper: a project's own tests run Git the same way, and the gate is the one place that starts them. (2) The gate's own `git diff` of the push keeps its environment: it reads the pushing repository, which is what it should act on. (3) `GIT_CONFIG_KEY_<n>`/`GIT_CONFIG_VALUE_<n>` go with `GIT_CONFIG_COUNT`.
- **Verified by:** `git-guards.test.mjs` (a real push from a linked worktree whose gate step runs `git init` and `git config core.hooksPath` in another folder leaves the repository's `core.bare` and `core.hooksPath` unchanged; failed with `core.bare = true` before the fix) and `gate.test.mjs` (the same step through `runGate` with `GIT_DIR` set to the worktree's Git folder; fails without `withoutRepositoryEnv`); `npm test` (584, 0 failed), lint, typecheck, `docs:check`. **Not verified:** on bot-rts itself.
- **Next step:** none; projects take the fix with the next version.
