# I-31 — The node-ts quiet test commands do not reach Jest from a workspaces root, and two quiet defaults are missing

**Status:** ✅ · **Agent:** C1 · **Size:** 1 SP · **Area:** stack adapters · **Reported:** —

**The node-ts quiet test commands do not reach Jest from a workspaces root, and two quiet defaults are missing**: the take of `0.5.0-dev.1` in AndLD/bot-rts (#304, flow 3, step 9b) found that the preset's default `testQuiet`, `npm test --silent -- --reporters=summary --silent`, prints as much as the plain command (1,102,645 characters against 1,095,160) where the root script is `npm run test --workspaces`: the flags after `--` go to npm, not to Jest. The form that works there is `npm run --silent test --workspaces --if-present -- --reporters=summary --silent` (271,778 characters, −75%); the same holds for `testCoverageQuiet`. The preset also gives no default for `typecheckQuiet` or `formatQuiet`, so a project writes its own (`npm run --silent typecheck`, `npm run --silent format -- --log-level warn`). The note of `0.5.0-dev.1` says neither. A fix: defaults that work from a single package and from a workspaces root (or the note says which form to write for each), the two missing defaults, and the note of `0.5.0` naming them; verified by a test of the commands the preset gives and by the next take.
