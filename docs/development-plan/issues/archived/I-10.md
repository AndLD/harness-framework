# I-10 — A flow continued from another account resumes a worker that account cannot find, and nothing falls back to a fresh one

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP · **Area:** runtime adapters · **Reported:** — · **Log:** [I-10.log.md](./I-10.log.md)

**A worker is resumed from an account that does not hold it.** A command-line worker of the session executor lives in the configuration folder of the
account that started it. The owner runs two accounts on one machine (two desktop apps, each with its own command-line folder), and a flow can be continued
from either. When step 1 ran on account 1 and the flow is continued on account 2, `harness flow dispatch` reads the worker from the log and decides to continue
it: `claude -p --resume <worker>` answers "No conversation found with session ID …" (checked on 2026-11-05), and neither `dispatch` nor the procedure
`run-flow` says what to do then. Even where the conversation can be found (two accounts sharing one folder), continuing it changes the account and finds no
warm cache. Found after task 5.5, when the owner split the command line by account.

**The fix:** (1) the log records the account a worker runs on (`**Account:**` beside `**Worker:**`); an executor may say how to read the orchestrator's account
(an optional operation `account`), the orchestrator passes it (`harness flow dispatch --account <id>`), and the reuse rule adds "the same account": a different
one starts a fresh worker, and an unknown one leaves the decision to the other conditions. (2) Whenever `dispatch` decides to continue a worker, it also prints
the fallback: if the continue fails for any reason, start a fresh worker with the start means, log it as fresh and the failed continue as a D0 decision; the
procedure `run-flow` says the same. Verified by the tests of the reuse rule (another account, an unknown one), of `dispatch` (the account in the log line, the
fallback printed with every continue), of the Claude Code adapter (the account means) and the conformance suite (an `account` that is not a list of means fails).
