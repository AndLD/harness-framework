# I-11 — a worker started on the command line has no permission to edit files or run commands, and the executor's means do not say how to give it

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP · **Area:** runtime adapters · **Reported:** — · **Log:** [I-11.log.md](./I-11.log.md)

**A worker started on the command line has no permission to edit files or run commands, and the executor's means do not say how to give it**: the `session` executor of the Claude Code preset (task 5.5) starts a worker on the command line with `claude -p --model … --effort … --output-format json`. In print mode the worker runs under the default permission mode, which asks before an edit or a command; nobody answers, so the tool call is refused. Found in the probe of task 5.9: a worker told to create one file reported `blocked`, saying that the write "was refused because write permission for that path has not been granted" (`permission_denials` in the JSON answer names the `Write` call); the probe continued it once with `--permission-mode acceptEdits` and it finished. A real step also runs Git, the checks and `gh`, so a worker would be blocked at its first command. The probe of 5.5 did not meet it because its workers only answered a question. Which mode a flow's workers run under is a security choice that belongs to the owner (`acceptEdits` allows edits only, a list of `--allowedTools` allows named commands, `bypassPermissions` allows everything), so a fix does not pick one silently: the flow's `executor` settings gain a `permissions` value (or the means read it from the project's settings), the means of `claude -p` pass it, `harness flow dispatch` says which mode a worker will run under and that the default blocks it, and the procedure `run-flow` tells the orchestrator what to do with a worker that reports a refused permission (continue it once with the mode the owner allowed, else escalate). The workers the desktop app starts with `start_session` run under the app's own permission settings and are not affected. Verified by a dispatch that prints the mode, a test of the means, and a probe in which a worker writes a file. Found by the agent of task 5.9.
