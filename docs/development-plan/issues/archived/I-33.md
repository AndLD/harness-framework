# I-33 — The migration tests take "the last release" from the newest tag, so they fail once a version is tagged

**Status:** ✅ · **Agent:** C1 · **Size:** 1 SP · **Area:** checks · **Reported:** —

**The migration tests take "the last release" from the newest tag, so they fail once a version is tagged**: `tests/migration/released-tags.test.mjs` takes `TAGS.at(-1)`, the newest `v*` tag of the repository, as the release a project takes the tree from. Once `v0.5.0` exists (flow 3, step 9f, 2026-11-07), the two tests of 6.8 ("a project of the last release that does nothing takes Phase 6…" and "…that sets the quiet commands…") take the tree from `0.5.0` to a tree that is `0.5.0` or older and fail, so every local push that runs the tests fails in a checkout that has fetched the tag; the pre-push check refused the push of the tag itself, which went up as the tag object with no local ref. CI passed, since its checkout had not the tag. The same root as I-17 (tests that depend on the tags present). A fix: "the last release" is the newest tag whose version is lower than the tree's version (a released tree takes the one before it), and a test of that choice on a tree equal to the newest tag; verified by the tests passing in a checkout with `v0.5.0` fetched, on `develop` after the merge-back.
