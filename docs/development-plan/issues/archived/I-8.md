# I-8 — A push from a linked worktree runs the gate's tests with the hook's `GIT_DIR`, and they rewrite the repository's Git config

**Status:** ✅ · **Agent:** C1 · **Size:** 2 SP · **Area:** Git rules · **Reported:** — · **Log:** [I-8.log.md](./I-8.log.md)

**A push from a linked worktree runs the gate's tests with the hook's `GIT_DIR`, and they rewrite the repository's Git config**: Git runs the
pre-push hook of a linked worktree with `GIT_DIR` set to `<repo>/.git/worktrees/<name>`, and the hook (`tools/git-hooks/pre-push`) hands that
environment to `harness gate`, which hands it to every step it starts. A test that runs Git in a temporary folder by `cwd` alone (`git init -q`,
`git config core.hooksPath …` in the tests of the bootstrap, the adoption, the links, the changes, the issue queue and the phase split) then acts on
the real repository: `git init` takes `GIT_DIR` for a bare repository, because it does not end in `/.git`, and writes `core.bare = true` into the
shared `.git/config`, and a bootstrap test rewrote `core.hooksPath` to `harness/tools/git-hooks`. Every later Git command of the checkout then fails
("this operation must be run in a work tree"). Found when the first push of pull request #83 ran from a Claude desktop worktree
(`.claude/worktrees/…`); reproduced on 2026-11-04 in a throwaway repository: a pre-push hook that runs a plain `git init` in another folder, pushed
from a linked worktree, sets `core.bare = true` on the main repository, and pushed from the main checkout (`GIT_DIR=.git`) does no harm. A project
that uses the framework runs the same hook and gate. A fix starts the steps of the gate, and the project's setup script of the hook, without the
variables that point Git at a repository (`git rev-parse --local-env-vars`); it is verified by a test that runs a step of the gate with `GIT_DIR`
set to a throwaway repository's worktree folder and finds that repository's `core.bare` and `core.hooksPath` unchanged.
