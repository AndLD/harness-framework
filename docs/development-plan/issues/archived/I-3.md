# I-3 — The migration adds the folders of the new plan layout to the layer map of a project with its own layers

**Status:** ✅ · **Agent:** C1 · **Size:** 3 SP · **Area:** profile file · **Reported:** [issue 62](https://github.com/AndLD/harness-framework/issues/62) · **Log:** [I-3.log.md](./I-3.log.md)

**The migration adds the folders of the new plan layout to the layer map of a project with its own layers**: a project whose `layers` role lists `<phases>/phase-*.md` but not the phase folders and the issue queue has 30 lines of `check layers` after `migrate` (`<phases>/phase-10-market-chat/10.1.md: belongs to no layer`), and `check paths` then reads the finished tasks of those folders, which the one-file phases were exempt from as state documents. The script of `0.2.0` edits the profile file for other keys; it adds `<phases>/phase-*/**` and `<issues>/**` to the layer that claims the one-file phases, where no layer claims them already, and says what it added (or what to add by hand, when the file cannot be edited safely). The note lists the action with its check (`check layers`). Verified by a test of the script on a profile with its own layers, and by running it twice. Reported by AndLD/bot-rts: [issue 62](https://github.com/AndLD/harness-framework/issues/62).
