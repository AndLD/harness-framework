# I-18 — A pull request that the update workflow brings up to date is left BLOCKED, because the required `pr-title` check of the new head never runs

**Status:** ✅ · **Agent:** C1 · **Size:** 2 SP · **Area:** checks · **Reported:** —

**A pull request that the update workflow brings up to date is left BLOCKED, because the required `pr-title` check of the new head never runs**: twice while flow 1 ran (the merge-back pull request of `0.3.0` and the pull request that closed Phase 5) the workflow `update-branches.yml` merged `develop` into a pull request's branch with the default token after another pull request merged. A push with that token starts no pull request run that the host accepts: the `pull_request` run of the new head ended `action_required` (it waits for a person's approval), and the run that the workflow dispatches by hand (`workflow_dispatch`) reports `changes`, `static checks` and `verify` as success but `pr-title` as skipped, so the pull request showed no checks and stayed `BLOCKED` with auto-merge on, and nothing woke anyone. Pushing an empty commit from a person's account started the normal run and the pull request merged. The comment of the workflow names the cure (a token of one's own, `AUTO_MERGE_TOKEN`, makes the host start the runs itself); a fix is either to make the dispatched run report `pr-title` for the pull request of the branch, or to state in the workflow's comment and the releasing guide that without `AUTO_MERGE_TOKEN` a pull request that was updated by the workflow needs an empty commit from a person, and to have the session's CI monitor name that case. Found by the orchestrator of flow 1.
