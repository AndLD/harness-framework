# I-14 — `harness flow status` takes a consumer's pull request for a development version as the take of the final version it extends

**Status:** ⬜ · **Agent:** C1 · **Size:** 1 SP · **Area:** checks · **Reported:** —

**`harness flow status` takes a consumer's pull request for a development version as the take of the final version it extends**: while flow 1 ran, the consumer's open pull request "chore(framework): take 0.3.0-dev.1" made the status of the step that takes `0.3.0` read 🟡 ("pull request #297 is open"), because the tool looks for the version `0.3.0` in the title as a substring and `0.3.0-dev.1` holds it. The same would make the take of `0.3.0-dev.2` read as the take of `0.3.0-dev.1` and the reverse. A fix matches the version as a whole token in the title (the version not followed by a character of a longer version, such as `-dev.1`, a digit or a dot-digit), for the pull requests and for the lock, and adds a test with a development version and its final version in two titles. Found by the orchestrator of flow 1.
