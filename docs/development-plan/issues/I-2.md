# I-2 — `migrate` counts a project that an older `sync` updated as `0.1.0`

**Status:** ⬜ · **Agent:** C1 · **Size:** 2 SP · **Area:** bootstrap and sync · **Reported:** [issue 61](https://github.com/AndLD/harness-framework/issues/61)

**`migrate` takes the start of a project that an older `sync` updated for `0.1.0`**: the `sync` of a version before `0.2.0` replaces `version` in the lock and writes no `migrations` record, so `migrate` counts the project as `0.1.0`: the lock says `migrations.start.version` `0.1.0` for a project that was at `0.1.1`, and the notes of the versions the project had taken are printed again (and their scripts would run again). The version the project was at is in the lock of its last commit, which the migration starts from: `migrate` reads it there (when it names another version than the lock now does), keeping `0.1.0` only for a lock that no commit holds. Verified by a test of a project whose sync left no record: the start names the version of the last commit and the notes before it are not printed. Reported by AndLD/bot-rts taking `0.2.0-dev.1` from `0.1.1`: [issue 61](https://github.com/AndLD/harness-framework/issues/61).
