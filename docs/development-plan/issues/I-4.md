# I-4 — The migration keeps a task that a branch claims, though it is still ⬜

**Status:** ⬜ · **Agent:** C1 · **Size:** 2 SP · **Area:** plan format · **Reported:** [issue 63](https://github.com/AndLD/harness-framework/issues/63)

**The migration keeps a task that a branch claims, though it is still ⬜**: the script of `0.2.0` turns every ⬜ task of the open-ended phase that no order names into an issue, so a task in hand (claimed by a draft pull request, not yet set to 🟡) became `I-3` and the phase was closed without it. The script leaves a task for which a branch of the repository (local or remote-tracking) is named `<type>/<task id>-<slug>`, which is how a claim is made, and the procedure `update-framework` says to set the task in hand to 🟡 before the `sync` (the order `start-task` gives, step 5). The note says it. Verified by a test of the conversion with a claim branch: the task stays in its phase. Reported by AndLD/bot-rts: [issue 63](https://github.com/AndLD/harness-framework/issues/63).
